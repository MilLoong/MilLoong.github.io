KMP算法——透彻的理论理解&代码理解（c++）

原文：https://blog.csdn.net/qq_30618989/article/details/149081820
此原文也是本人所写

前言

相信大家在学 字符串算法 的时候第一个接触的就是 kmp算法 ，因为 字符串匹配问题 太经典了，而kmp算法竟然能把一个 O(mn) 的时间复杂度用及其妙的前缀表来优化到线性的时间复杂度 O(m+n)。 不过虽然 kmp算法 是 字符串算法 中及其重要的算法，但实际上还是比较难理解的。

以博主的经验来看，网上所讲的 kmp算法 以及 next数组（prefix数组） 的理解其实都差点意思，最后是我冥思苦想许久才彻底搞明白 kmp算法到底在讲什么 、 next数组（prefix数组） 到底代表什么含义，以及怎么理解的。所以本文就以我的理解，来给各位透彻的解释一下 kmp算法，以及它的代码 是怎么理解的，虽然可能不是最透彻最简洁的，但我想应该是会比网上绝大部分文章讲得通俗易懂的，相信你应该可以看懂。

理论理解

基本定义

kmp算法 涉及 字符串匹配问题， 其中有许多需要我们理解的 定义 ，而有些博客对这些定义基本不谈或者草草而过，我认为这是不妥的，有可能会对我们理解 kmp算法 造成阻碍。所以在本篇文章来详细讲讲这些 定义 ：

一：文本串，模式串

文本串 ：要在其中查找 模式串 的 目标字符串

模式串 ：要在 文本串 中查找的 字符串

比如：

文本串（S）： abcabacabcacbab

模式串（P）： aba

那么 字符串匹配 其实就是要在 S 中找到等于 T 的子串 ， 并有可能重复出现 。

二：前后缀，相等前后缀

有些文章对 前后缀 貌似是以为我们都懂，讲述是直接省略了的。但我认为呢，既然要讲定义就要讲得详细一点，所以在本文就详细解释一下 前后缀：

前缀： 字符串 从头开始 ，不包含 整个字符串本身 的 连续子串 。

直接说不容易明白，举个例子：

字符串： abcde

前缀：

a

ab

abc

abcd

而没有abcde

后缀： 字符串 从尾开始 ，不包含 整个字符串本身 的 连续子串 。

还是上述例子：

字符串： abcde

后缀：

e

de

cde

bcde

而没有abcde

特别地，长度为1的字符串比如"a"，没有前后缀。

理解了前后缀之后，我们就可以定义 相等前后缀 了（网上好像有的说的都是公共前后缀，不过我觉不太好理解，前缀和后缀相等比较好理解） ：

相等前后缀：既是字符串的前缀，也是字符串的后缀， 但 不等于整个字符串自身。

比如：

字符串： ababa

前缀：

a

ab

aba

abab

后缀：

a

ba

aba

baba

相等前后缀（就是在前缀中挑一个Sa和后缀中挑一个Sb，且Sa=Sb=S，相等前后缀就是S）：

a

aba

注： 实际在手算相等前后缀的时候，可以先从前缀开始看，遍历每一个前缀，然后看每一个前缀对应的相等长度的后缀是否和前缀相等，如果相等的话该前缀就是相等前后缀

同样，长度为1的字符串比如"a"，没有相等前后缀

这样子理解的话应该是能对前后缀及相等前后缀理解得比较通透的。

三：next数组（prefix数组）

这个数组可以称得上是 kmp算法 的关键了，所以有必要详细解释。

next数组（prefix数组） 是针对 模式串 来定义的。实际上，这个数组的中文名称应该叫做 前缀表 ，我的理解的话是 相等前缀表 ，这样的话听这个名字就知道是干嘛的了： 假设现在遍历到位置 i，那么就是求从起点到位置 i 的子串的最长相等前后缀长度。

举个例子，可以稍微手算一下：

字符串： ababa

索引        字符串 最长 相等前后缀 最长 相等前后缀长度

i=0             “a”                    无                                    0

i=1            “ab”                   无                                    0

i=2           “aba”                 “a”                                    1

i=3          “abab”               “ab”                                   2

i=4         “ababa”             “aba”                                  3

所以：

前缀表：[0,0,1,2,3]

可以看到貌似 prefix数组 是比较符合名称的，那叫 next数组 又有什么意义呢？这个我们在后面用程序求 前缀表 的部分会详细讲到，这里就预告一下： next就是指，指针 j 要跳转到的下一个位置。

相信大家在初学时应该会和我有同样的疑问：为什么要定义这么个 next数组 呢？

其实这就是 kmp算法的妙处 所在了：利用 最长相等前后缀 来避免 多余的遍历 ，从而优化成 线性时间复杂度 。

这个的理解我会在后面 基本原理 的部分讲到

四：指针 i 和指针 j

这部分主要是细说一下 代码部分 的两个指针。

这部分的定义我目前在网上没看到详细讲的，但是我觉得对理解代码还是很重要的，不讲通的话不好理解算法本身。所以这里也详细讲一下：

求next数组时：

next数组 肯定不能靠手算的，那么我们在 用程序求next数组 的时候其实是不那么简单的。这里就定义两个指针来辅助代码的书写，其中 指针 i 和 指针 j 都是关于 模式串 的：

指针 i ：用来从左到右遍历模式串的每一个字符（当然也是next数组的下标了）

指针 j ：指向模式串的某个前缀末尾（末尾指的是前缀最后一个字符的下一个，不要搞错；注意这里说的是“某个”，事实上，在写代码的时候 j 会不断进行移动的，所以它将会是许多个前缀的末尾，在后面原理讲解的时候就知道了）， 如果 字符串下标从0开始，那么也代表从起点到 当前位置之前的一个位置的这个子串前缀的长度（这点很重要，很多教程都没说 j 代表子串前缀的长度。）

这个 指针 j 的意义大概是这样的：

假设 模式串 ：abcab

相等前后缀是：ab

指针 j 的意义就是：

j=2

↓

a b | c | a b

0 1   2   3 4

可以看到： ab的长度= j =2

这里的 指针 i 就是正常遍历，不难理解。但 指针 j 可就有讲究了，是 kmp算法的核心部分 ，所以一定要深入理解上面的定义，不然理解kmp算法就会变得很困难。

进行字符串匹配时

为了 遍历文本串和模式串 ，我们可以定义 关于S的指针 i 和关于T的指针 j ：

指针 i ：用来从左到右遍历S的每一个字符，不会回退（这个不会回退是保证kmp算法时间复杂度是O(m+n)的关键）

指针 j ：和求next数组的指针 j 定义一样，注意是关于模式串T的

比 求next数组 时的两个指针的定义要简单一点，所以 重点理解求next数组的两个指针的定义 就好了。

基本原理

求next数组

在真正进行字符串匹配的时候，我们先来求一下 next数组。

用这个 模式串 作例子：

s： bccbccb

我们前面说过，其实 next数组就是前缀表，next[i]代表的是 0 - i 子串的最长相等前后缀的长度 ，所以其实我们口算next数组的话是比较简单的， 真正难的在于用代码实现 （也就是后面代码的部分），所以这里就仅是简单说一下口算next数组，步骤：

（1）遍历每个 i ，找到对应的 0 到 i 的子串。

（2）对于每个子串，遍历每个前缀，然后看位置对应，相等长度的后缀是否和该前缀相同。

这个（2）的话可以举个例子：

对于子串（不一定是上面的s的子串，这里随便举个例子）：ababa

前缀                对应的后缀                是否是上述子串的相等前后缀

“a”                        “a”                                              是

“ab”                      “ba”                                            否

“aba”                    “aba”                                          是

“abab”                  “baba”                                        否

最长相等前后缀 是"aba"，长度为4

从上面那个例子来看，我们可以通过下面这个表来清晰看到求next数组的过程：

遍历字符串s：

子串                        对应最长相等前后缀                next[i]

i=0                 “b”                                       无                                    0

i=1                 “bc”                                     无                                    0

i=2                 “bcc”                                   无                                    0

i=3                 “bccb”                                 “b”                                   1

i=4                 “bccbc”                               无                                     0

i=5                 “bccbcc”                              无                                    0

i=6                 “bccbccb”                          “bccb”                                4

这样手动就可以求出next数组了

可以看到 我们手动求next数组的话其实并不是那么麻烦，但如果要用程序的话，这样求就太耗时间了，所以实际上重点是理解代码是怎么求next数组。

进行字符串匹配

我们在 基本定义的时候 提到：

kmp算法的妙处 所在：利用 最长相等前后缀 来避免 多余的遍历 ，从而优化成 线性时间复杂度 。

这个怎么理解呢？举个例子：

文本串（S）： bcbccbcbcb

模式串（P）： bcbcb

（P）的next数组：0 0 1 2 3

如果说用暴力匹配的方法，我们是 先有遍历S的 i 和遍历P的 j ，然后双重for循环，那这样我们知道是不行的，时间复杂度是O(mn)

但实际上我们可以发现， 在每次发现不匹配后，实际上不用再从s[i+1]开始了，而是可以利用最长相等前后缀来进行处理的。 文字说的有点抽象，可以拿画图来说明：

首先是暴力算法：

如上图①， 红色框就是模式串P以及其在S中相等的部分，而绿色框就是S中与T不相等的地方。

暴力算法的话就是直接遍历每个文本串S的位置，然后对于每个 i ，再在P中遍历 j ，如果匹配的话就 j 就往前，不匹配就移动 i ，这个过程在上图中就是从图①到图②。

kmp算法：

kmp算法的话就是利用最长相等前后缀。 在上图中蓝色框就是 0 到 i-1 子串的最长相等前后缀， 那我们可以从图中看到 ，实际上如果s[i]和p[j]不匹配的话，我们移动指针的时候，其实就只需要移动 j 到 0 到 i-1 子串的最长相等前后缀的末尾，接着继续看s[i]和p[j]匹不匹配就好了。

如果不匹配的话就继续往前面的最长相等前后缀的末尾去跳（就是最左边蓝色框的最长相等前后缀的末尾），直到p[j]=s[i]或者 j 不能再移动（j=0时）为止。

如果匹配的话就能继续往后匹配（比如上图②中，如果p[j]=a，那么“s的右边蓝色框+a”=“p的左边蓝色框+p[j]”，然后继续看 j 后面的模式串是否和 i 后面的文本串是否匹配就行了）（图中字符串P实际上是没有“移动”的，实际上是 j 移动，这里这样画是为了让 j 和 i 对齐，便于观察）。

那么这样就有 两个好处：不用移动文本串的指针 i ； j 移动的范围是取决于最长相等前后缀长度的，所以移动的范围可以变得很大。

所以这就是为什么 kmp算法 可以把时间复杂度降为 O(m+n) 了。

理解了之后，上面的那个具体的例子用 kmp算法 就是这样进行匹配的：

文本串（S）： bcbccbcbcb

模式串（P）： bcbcb

（P）的next数组：0 0 1 2 3

代码理解

了解了定义之后我们就可以来讲一下 kmp算法 的代码了，讲讲这个 代码 究竟怎么理解。

注：本篇博客的代码是用c++写的，然后的话字符串下标是从0开始的，我并没有只用一个while循环来完成全部判断而不用在外边写if（有的博客可能引入一个k，然后在while循环里完成整个判断），然后next[0]初始化是0，这可能与别的博客讲的不同（有的博客可能会初始化成next[0]=-1，不过我理解的是既然next是前缀表，表示前缀长度，就不能出现负数，所以稍微引入了一个[虚前缀]的假想概念），不过我能保证代码是相对简单的。

求next数组

为了方便理解，可以 先给出代码，然后解释，最后再给一个带注释的代码便于理解 。

代码如下：

//定义的变量
next[max_len];
string t,s;//t是文本串，s是模式串
 
//代码部分：求next数组
int j=0;
next[0]=0;
for(int i=1;i<s.length();++i){
    while(j&&s[i]!=s[j])j=next[j-1];
    if(s[i]==s[j])++j;
    next[i]=j;
}

我们求next数组的是这样的：

（1）初始化 j=0 ，可以理解成开始的时候 j 是在最开头假想的“虚前缀”的末尾，也就是第一个元素的位置（大概就是："[虚前缀]abcdcba"）

（2）遍历模式串，索引 i 从 1 开始 （因为第一个元素肯定没有前后缀，那么next[0]=0就是已知的。） ，将s[i]与s[j]比较：

①如果s[i]=s[j]， 那么直接 j ++ 就好了，也就是前缀长度+1，或者说前缀末尾向后移一格

②如果s[i]!=s[j]， 这个时候情况比较复杂，但也是 kmp算法的精髓 ，从代码中可以看到，我们做了这样一个操作：

while(j&&s[i]!=s[j])j=next[j-1];

这个是怎么理解的呢？我们说过 next数组也就是前缀表，它存储的是从起点到当前位置的子串的最长相等前后缀的长度 ，那么 如果模式串的下标是从0开始的话，存储的也是前面的最长相等前后缀的末尾 ，所以这段代码的意义其实就是： 将指针 j 移动到前面的最长相等前后缀的末尾，直到s[i]=s[j]或者 j 移动不了为止 。举个例子：

图是用windows自带的画图画的，有点粗糙，见谅

如下图①，假设现在遍历到 i ， 红色框部分就是已经遍历的子串的最长相等前后缀 ， 黑色框部分就是不属于最长相等前后缀的部分，根据 j 的定义知此时 j 应该是最长前后缀子串的前缀的末尾 ，所以位置如图①。

然后此时 s[i]!=s[j] ，然后的话 j 应该是要跳到 左边红色框部分前面的最长相等前后缀的末尾，就是图②中 j 的位置， 这个应该看图应该好理解，相当于你要 找到 0 到 (i-1) 这个子串前面的最长相等前后缀的末尾，就是图①中最左边绿色框后面的那个位置，记作pos，然后比较一下s[pos]和s[i]，如果相同的话“最左边绿色框+pos”就和“最右边绿色框+i”相等，那么这就是 0 到 i 子串的最长相等前后缀。 而 next[j-1] 就是 左边红色框部分的最长相等前后缀的长度，同时也是左边红色框部分的前面的最长相等前后缀的末尾（因为字符串下标从0开始，这个如果没看懂的话可以看看“基本定义”中关于指针 j 意义的理解，和这里的理解差不多）。

如果 j 跳位置了之后s[j]和s[i]还是不相等，那么就继续跳，直到s[j]=s[i]或 j 不能往前跳为止（也就是 j =0），就像下图中②跳到③的过程， 这也就是为什么我们要用while而不是if，因为要跳的不止一次。

而 如果s[i]=s[j]（如图③）或者 j 不能往前跳了（也就是 j =0） ，那么 j 就可以停下了。

从这个操作中我们也 可以理解为什么要叫next数组，其实就是 j 跳到的下一个位置嘛 。

注：可以看到代码中我们是先移动 j 的位置，再判断 j 是否相等的，也就是先判断s[i]!=s[j]，然后再判断s[i]=s[j]。 这个好理解， 我们肯定是先移动 j 到s[i]=s[j]的地方（情况1）或 j 不能移动（也就是 j =0的地方）（情况2），然后再让 j 变成前缀末尾。

情况1 可以从上图③中理解，此时 next[i]应该是要等于黄色框的长度的，所以要让 j ++，也就是变成黄色框的末尾， 否则j就代表黄色框内蓝色小框的长度。

情况2 中， 如果s[i]=s[j] ，那么 0 到 i 子串的 最长相等前后缀 就是 只有s[0]一个字符的字符串 ， j 的长度同样要+1，变成"s[0]“的末尾，也就是要让 j ++； 而如果s[i]!=s[j] ，说明整个 0 到 i 子串没有相等前后缀， j 应该是要变成[虚前缀]的末尾，那也就是让 j 不动；

而你 如果先判断s[i]=s[j]的话，那么就会在开始的时候 j 就往前动了一格，而最后 j 会停在如上图③中的位置而不是前缀末尾，这会造成后面更新next[i]时出现错误。

（3）更新next数组，也就是next[i]= j ，这个可以从前缀表的意义理解，next[i]就是 0 到 i 子串的最长相等前后缀的长度，而我们在（2）中已经更新 j 到正确的位置了， j 的意义就是最长相等前后缀的长度。

带注释的代码：

//定义的变量
next[max_len];
string t,s;//t是文本串，s是模式串
 
//代码部分：求next数组
int j=0;//初始化j
next[0]=0;//初始化next[0]
for(int i=1;i<s.length();++i){//遍历s
    //先处理s[i]!=s[j]，再处理s[i]==s[j]
    while(j&&s[i]!=s[j])j=next[j-1];//处理s[i]!=s[j]
    if(s[i]==s[j])++j;//处理s[i]==s[j]
    next[i]=j;//更新next[i]
}

那么这就是求next数组的代码解释了。

要说明的是，上面那个 s[i]!=s[j] 的处理的情况的图我好像没在别的博客发现有雷同的，因为别的博客基本上都是用具体的例子来做解释，不过我初学的时候总觉得 拿具体的例子来理解kmp算法差点意思， 所以在这篇博客中举了一个 比较抽象，一般的例子 ，自认为比具体的例子好理解，如果大家觉得用具体的例子比较好的话，也可以去看看其他的博客了。

进行字符串匹配

还是 先给代码，再给解释，最后给带注释的代码便于理解：

//i,j的含义在基本定义里讲有
//t是文本串，s是模式串
j=0;
for(int i=0;i<t.length();++i){
    while(j&&t[i]!=s[j])j=next[j-1];
    if(t[i]==s[j])++j;
    if(j==s.length()){
        cout<<i-s.length()+1<<endl;
        j=next[j-1];
    }
}

其实这个代码是和 求next数组 差不多的。不同点在于： i 是遍历文本串的指针，是不用回退的，一直往下走的，而如果s[i]!=s[j]，也就是说不匹配的话， j 要回到前缀的位置，这个我们在“基本原理”那里讲过。

具体过程如下：

（1）初始化 j =0，就是从模式串的第一个字符开始匹配

（2）用指针 i 遍历文本串，还是两种情况：

①t[i]==s[j]，直接让 j ++就好，这里的意义就是当前s[j]已经匹配了，让 j ++去匹配模式串的下一个字符

②t[i]!=s[j]，那么就让 j 跳到前缀末尾，这里的话在“基本原理”已经讲过了，就是用最长相等前缀去避免重复的比较嘛。举个例子：

可以发现， 从图①到图②实际上就是把 j 移动到next[j-1]，相当于s中前面的最长相等前后缀和t中后面的最长相同前后缀已经是匹配的了，然后继续看t[i]和s[j]是否相等，相等的话就继续往下匹配（也就是在图②中在紫色框匹配，前面的不用管了），不相等就继续跳 j 就好了（s是实际上没有“移动”的，这里图上是为了让 j 和 i 在视觉上是对齐的，便于理解）

（3）如果 j ==s.length()，也就是说 j 在模式串s的末尾了，那么就已经匹配完了一个模式串，由于 这时候 i 应该是会在文本串的 0 到 i 子串的最后一个位置（也就是对于遍历时的每个 i ，开始时 j 始终在 i 的后一个位置），并且s的长度是s.length()，所以 其起始位置就是i-s.length()+1（下标从0开始），我们就可以输出它的起始位置了。然后 j 继续回到前缀末尾，相当于接下来要继续匹配下一个位置。还是举个例子：

图①中是匹配成功的状态 ，可以发现 起点位置就是i-s.length()+1，图②是利用最长相等前后缀来移动指针 j 。

带注释的代码：

j=0;//初始化j
for(int i=0;i<t.length();++i){//遍历i
    while(j&&t[i]!=s[j])j=next[j-1];//处理t[i]!=s[j]
    if(t[i]==s[j])++j;//处理t[i]==s[j]
    if(j==s.length()){//处理匹配成功的情况
        cout<<i-s.length()+1<<endl;//输出起始位置
        j=next[j-1];//j移动到前缀末尾，继续匹配下一个位置
    }
}

其实从代码中我们也可以发现， 真正进行字符串匹配的时候，指针 i 是不会变的，而变的只是指针 j ，然后我们就利用最长相等前后缀，来避免重复的比较，从而把时间复杂度优化成线性。
