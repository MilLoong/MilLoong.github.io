  • 实现一个网络应用，分为服务端和客户端。客户端将某种请求发给服务端，服务端收到请求，将结果发回给客户端。例如，你要实现的请求功能可以是询问四则运算的结果，或者是提供prompt进行大模型推理。应用层协议由你自己设计。

    • 客户端

      • 我这里实现的 客户端 请求功能 就用 询问四则运算结果 了吧

      • 启动客户端

        • 首先，要实现 客户端 和 服务端 之间的 通信和连接，可以使用 Socket（套接字）

        • **Socket（套接字）**是 计算机网络编程 中用于 进程间通信 的 媒介

        • 而在 Python 中的这个 Socket 库就可以帮我们 写出客户端或服务器端程序

        • 然后 客户端 要做的就是，主动连接服务端，与服务端通信

        • 我写的这个 客户端 的 交互 就是，让用户一直输入 四则运算，除非输入 exit

        • 应用层协议

          • 这个 应用层协议，我就简单设计一个吧：

            格式：

            • command:msg

            其中：

            • command：
              • calc：计算请求，一般是 客户端 用，向 服务器 发送 计算请求
              • res：计算结果，一般是 服务端 用，返回 计算结果 给 客户端
              • error：如果出错了，比如 除以0 或 某些 非法字符 使得程序出错，返回这个
            • msg：
              • 返回的信息

            比如：

            • calc:1+1：客户端 发送请求，让 服务端 接收 并 计算 1+1 的结果
            • res:2：服务端 返回 1+1 的 计算结果 给 客户端 接收

        • 代码（./client.py）

          • import socket


def start_client():

    # 启动客户端


    # 创建 socket 对象

    socket_client = socket.socket()


    try:

        # 连接到服务器

        socket_client.connect(("localhost", 8080))

    except ConnectionRefusedError as e:

        print(f"服务端未打开: {e}")

        return


    try:

        while True:

            send_msg = input()


            # 如果是 exit 就退出

            if send_msg == "exit":

                break


            # 构造 请求头

            request = f"calc:{send_msg}"


            # 发送消息到 服务端

            # 注意是以 字节流 形式发送

            socket_client.send(request.encode("UTF-8"))


            # 接受 服务端 的信息

            # 1024是 接收端 缓冲区大小

            recv_data = socket_client.recv(1024).decode("UTF-8")

            if not recv_data:

                print("服务端已关闭")

                break


            # 解码 响应头

            if ":" in recv_data:

                command, msg = recv_data.strip().split(":", 1)


                if command == "res":

                    print(msg)

                elif command == "error":

                    print(f"错误: {msg}")

                else:

                    print(f"未知响应头: {command}:{msg}")

            else:

                print(f"响应头格式错误, {recv_data}")

    except ConnectionAbortedError as e:

        print(f"服务端已终止: {e}")

        return

    except Exception as e:

        print(f"错误: {e}")

        return

    finally:

        # 关闭连接

        socket_client.close()


if __name__ == "__main__":

    start_client()

def start_server():

    # 启动服务端


    # 创建 socket 对象

    socket_server = socket.socket()


    # 绑定ip和端口, 表明是服务端

    socket_server.bind(("localhost", 8080))


    # 监听一个端口

    socket_server.listen(1)


    try:

        # 等待客户端连接

        print("等待客户端连接...")

        conn, address = socket_server.accept()

        print(f"已连接, 客户端的信息：{address}")

    except Exception as e:

        print(f"连接客户端失败: {e}")

        return


    try:

        while True:

            # 接收信息

            # 1024是 发送端 缓冲区大小

            data: str = conn.recv(1024).decode("UTF-8")

            if not data:

                print("客户端已断开")

                break


            # 解码 请求头

            if ":" in data:

                command, msg = data.strip().split(":", 1)


                if command == "calc":

                    print("收到计算请求")


                    # 计算结果

                    result = calc(msg)


                    # 构造 响应头

                    if result.startswith("Error"):

                        response = f"error:{result}"

                    else:

                        response = f"res:{result}"

            else:

                response = f"error:请求头格式错误"


            # 回复消息

            conn.send(response.encode("UTF-8"))

    except Exception as e:

        print(f"发生错误: {e}")

        return

    finally:

        # 关闭连接

        conn.close()

        socket_server.close()


if __name__ == "__main__":

    start_server()

      • Linux 平台

        • eBPF 方案

          • 该部分文件在 ./Linux/eBPF/base 下

          • eBPF 全称 extended Berkeley Packet Filter，中文是 扩展的伯克利包过滤器

            一般来说，要 向内核添加新功能，需要 修改内核源代码 或者 编写 内核模块 来实现

            而 eBPF 允许程序在 不修改内核源代码，或 添加额外的内核模块 情况下运行

            为了编写 加载和控制 eBPF 程序 的代码，需要安装 libbpf 和 bpftool，同时用 clang 编译

          • cgroup (控制组) 是一种 Linux 内核功能，用于 管理和隔离进程组的资源（如 CPU、内存）

            后续我们会将 客户端进程 加入到 cgroup 当中

          • BPF_PROG_TYPE_CGROUP_SOCK_ADDR 是一个 eBPF 程序类型，用于 拦截 socket 地址相关系统调用，比如：connect(), bind(), getpeername() 等

            它允许我们 附加 到一个 cgroup，然后挂载到 BPF_ATTACH_TYPE_CGROUP_INET4_CONNECT 这个 **hook点 **上（这里我就仅限 IPv4 连接了，也就是说 IPv6 这些是不会被 NTR 的）

            当该 cgroup 中的 任何进程发起网络连接（如 connect() 系统调用）时，我们的 eBPF 程序就会被触发

          • 原理

            • 先创建 cgroup

            • 然后编译 eBPF 程序（redirect.c）得到 redirect.o，然后去 加载和挂载 eBPF 程序 到 BPF_ATTACH_TYPE_CGROUP_INET4_CONNECT 这个 hook点 上

              这个 hook点 实际上就是 connect() hook点，当程序执行 connect() 时会执行这个 eBPF程序

            • 然后把 客户端 加入到 cgroup 当中

            • 最后，eBPF 程序 在 connect() 执行前被调用

              它检查连接的 目标地址和端口，如果发现目标是 127.0.0.1:8080，程序会直接在内核内存中将目标端口修改为 9090。然后内核会继续执行 connect()，但此时它连接的目标已经是 NTR 服务端了

            • 所以实际上现在这个 方案 只是 在客户端不知晓的情况下，改变了 客户端 连接的服务端，并没有涉及 数据包的劫持和篡改，是发生在 客户端和服务端建立连接之前 的，只是一个 重定向 过程

              后面的 附加部分 需要 换种方案

int bpf_redirect_connect(struct bpf_sock_addr *ctx) {


    // 检查是否为 IPv4

    if (ctx->user_family != AF_INET) {

        // 1 = SK_ACCEPT, 即允许

        return 1; 

    }


    // 检查 127.0.0.1:8080

    if (ctx->user_ip4 == bpf_htonl(INADDR_LOOPBACK) && ctx->user_port == bpf_htons(8080)) {


        // 篡改目标端口

        ctx->user_port = bpf_htons(9090);

        bpf_trace_printk(msg, sizeof(msg));

    }


    // 允许连接, 无论是原始的还是被篡改的

    return 1; 

}

          • 你对数据包的截获或者篡改处理过程是在网络传输的哪个步骤发生的

            • OSI 层面

              • Socket 就是 应用层 和 传输层 之间的 软件抽象层，而这个 ePBF 方案 实际上就是在 connect() 这个 api 上进行 处理 的，所以步骤的话其实就是 应用层 和 传输层 之间

            • 系统调用层面：

              • 应用程序 调用 connect(fd, addr, len)
              • 进入 内核空间 执行 sys_connect()
              • 在内核处理 connect 请求之后，三次握手之前，eBPF 程序被触发
              • eBPF 修改目标地址
              • 然后 内核 继续用修改后的地址进行 TCP 三次握手

            • 总之，数据包的截获或篡改（这里实际上只有数据包发送的目标地址被篡改） 发生在 TCP 建立连接的准备时期（篡改目标地址之后才进行连接），是在 应用层 和 传输层 之间的 步骤

              具体来讲，是在 应用程序 调用 connect() 系统调用后，TCP 三次握手 建立连接 前

          • 是在操作系统的哪个位置或者组件中发生的

            • 在 操作系统 的 应用层 和 传输层 之间的这个位置 发生的，准确来说是 Socket 层
            • 同时，eBPF 程序 也被 加载 到了 内核空间，所以也在 内核空间 中发生
            • 然后，这个方案用到了 cgroup 机制，所以它也发生在 cgroup 上，发生在 BPF_ATTACH_TYPE_CGROUP_INET4_CONNECT 这个 hook点 上

        • iptables 方案

          • **netfilter/iptables（简称为iptables）**组成Linux平台下的 包过滤防火墙，与大多数的Linux软件一样，这个包过滤防火墙是免费的，它可以代替昂贵的商业防火墙解决方案，完成封包过滤、封包重定向和网络地址转换（NAT）等功能，其中：

            iptables 是 Linux防火墙的管理工具，位于 /sbin/iptables

            netfilter 实现防火墙功能，它是 Linux内核中实现包过滤的内部结构

            当然，iptables 不仅能 管理防火墙，还能帮我们 管理数据包

          • 原理

            • iptables 有 四表五链，而我们这里要 重定向 到 NTR 服务端，可以使用 nat表，其用于 修改数据包的IP地址、端口号等信息（网络地址转换，如SNAT、DNAT、MASQUERADE、REDIRECT）
            • 然后 数据包 向外发送 会经过 OUTPUT 链，所以我们只需要在 OUTPUT 链 上附加 REDIRECT 这个 规则 就可以了
            • 当然这里只是 重定向，不能解决 附加任务 中的 篡改数据包，到 附加任务 是不能 只依靠 iptables 解决，具体的方案到下面再说

          • 你对数据包的截获或者篡改处理过程是在网络传输的哪个步骤发生的

            • OSI 层面

SEC("tc")

int tc_ingress_tamper(struct __sk_buff *skb) {

    void *data = (void *)(long)skb->data;

    void *data_end = (void *)(long)skb->data_end;


    // 解析 以太头

    struct ethhdr *eth = data;

    if ((void *)(eth + 1) > data_end)

        return TC_ACT_OK;


    // 只处理 IPv4

    if (eth->h_proto != __constant_htons(0x0800))

        return TC_ACT_OK;


    // 解析 ip 头

    struct iphdr *ip = (void *)(eth + 1);

    if ((void *)(ip + 1) > data_end)

        return TC_ACT_OK;


    // 只处理 TCP

    if (ip->protocol != IPPROTO_TCP)

        return TC_ACT_OK;


    // 解析 TCP 头

    struct tcphdr *tcp = (void *)ip + (ip->ihl * 4);

    if ((void *)(tcp + 1) > data_end)

        return TC_ACT_OK;


    // 检查是否是来自 9090 的响应

    if (ip->saddr == __constant_htonl(0x7F000001) && __constant_ntohs(tcp->source) == 9090) {

        // 从 TCP 首部指针偏移 TCP 头长度, 取得 TCP 负载数据的起始地址

        void *payload = (void *)tcp + (tcp->doff * 4);


        // 篡改 payload

        char replacement[] = "res:191981";


        #pragma unroll

        // unroll 是用来展开的

        for (int i = 0; i < 10; i++) {

            // 把 replacement 的 10 个字节 逐字 写回到 数据包 中

            long offset = (long)(payload + i) - (long)data;

            bpf_skb_store_bytes(skb, offset, &replacement[i], 1, BPF_F_RECOMPUTE_CSUM);

        }


        char msg[] = "TC Ingress: Tampered 114514 -> 1919810\n";


        bpf_trace_printk(msg, sizeof(msg));

    }


    return TC_ACT_OK;

}

from netfilterqueue import NetfilterQueue

from scapy.all import IP, TCP, Raw


def process_packet(pkt):

    # 回调函数，用于处理 NFQUEUE 传来的每一个数据包

    try:

        # 将原始数据包解析为 Scapy 对象

        scapy_pkt = IP(pkt.get_payload())


        # 检查数据包是否包含 TCP 负载 (Raw)

        if scapy_pkt.haslayer(TCP) and scapy_pkt.haslayer(Raw):

            payload = scapy_pkt[Raw].load


            # NTR 逻辑：查找并替换内容

            if b"res:114514" in payload:

                print("检测到 '114514'，正在篡改为 '191981'...")


                # 执行替换

                new_payload = payload.replace(b"res:114514", b"res:191981")


                # 将修改后的 payload 放回 Scapy 包

                scapy_pkt[Raw].load = new_payload


                # Scapy 会自动重新 计算长度 和 校验和

                # 删除旧的校验和, 让 Scapy 重新生成

                del scapy_pkt[IP].len

                del scapy_pkt[IP].chksum

                del scapy_pkt[TCP].chksum


                # 将 Scapy 包转换回 字节流，并设置回 NetfilterQueue

                pkt.set_payload(bytes(scapy_pkt))


    except Exception as e:

        print(f"[NFQUEUE] 解析数据包失败: {e}")


    # 接受数据包, 将其放回内核网络栈

    pkt.accept()


def main():

    print("等待来自 NTR 服务端 的数据包...")

    nfqueue = NetfilterQueue()


    # 绑定到 0 号队列

    nfqueue.bind(0, process_packet)


    try:

        nfqueue.run()

    except KeyboardInterrupt:

        print("\n正在关闭 NFQUEUE...")

        nfqueue.unbind()


if __name__ == "__main__":

    main()

            str_data = packet.payload.decode('utf-8').replace('res:114514', 'res:191981')

            packet.payload = str_data.encode('utf-8')

        print(f"改后数据包:\n{packet}")

        # 重新注入网络

        w.send(packet, recalculate_checksum=True)

        • 你对数据包的截获或者篡改处理过程是在网络传输的哪个步骤发生的

          • OSI 层面
            • 由于 WinDivert 驱动 在 网络层 和 数据链路层 之间
            • 所以相当于发生在 网络层 和 数据链路层 之间
          • 总之，数据包的截获或者篡改处理过程 是 发生在 网络层 和 数据链路层 之间

        • 是在操作系统的哪个位置或者组件中发生的

          • 由于用到了 WinDivert 驱动，所以是在 WinDivert 驱动 发生的
          • 由于涉及 windows网络堆栈，所以在 windows网络堆栈 上发生的，同时还涉及 WFP (Windows Filtering Platform) 组件
