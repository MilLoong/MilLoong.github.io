深入了解 冒泡排序

前言

相信大家只要学过 排序算法，都对 冒泡排序 有所了解，知道是个 稳定的排序算法，它的 时间复杂度 是 $O(n^2)$

基本的 冒泡排序 其实很简单：

// 向后冒
void bubble_sort(std::vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n - 1; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
            }
        }
    }
}

// 向前冒
void bubble_sort(std::vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n; ++i) {
        for (int j = n - 1; j >= 1; --j) {
            if (a[j] < a[j - 1]) {
                std::swap(a[j], a[j - 1]);
            }
        }
    }
}

具体的逻辑就是：

  • 循环 $n$ 次，每次去让 当前最大的放到后面（向后冒） 或 当前最小的放到前面（向前冒）

然后还有一些优化的版本是：

// 向后冒
void bubble_sort(std::vector<int>& a) {
    int n = a.size();
    for (int i = n - 1; i >= 0; --i) {
        bool f = 0;
        for (int j = 0; j < i; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
                f = 1;
            }
        }
        if (!f) {
            break;
        }
    }
}

// 向前冒
void bubble_sort(std::vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n; ++i) {
        bool f = 0;
        for (int j = n - 1; j > i; --j) {
            if (a[j] < a[j - 1]) {
                std::swap(a[j], a[j - 1]);
                f = 1;
            }
        }
        if (!f) {
            break;
        }
    }
}

不过它们理论上来说 时间复杂度 都是 $O(n^2)$ 的，所以本文不重点讲 如何写出冒泡排序的代码

而本文想告诉你，冒泡排序 并不仅仅 局限于上面的过程，还可以从 正确性、数学、变体、硬件 这些层面继续展开分析

正确性：不变量 与 early-stop

以 向后冒 为例：

  • 第 $1$ 趟结束后：最大值一定在 a[n-1]
  • 第 $k$ 趟结束后：最大的 $k$ 个元素已经按序固定在末尾

这就是冒泡的 不变量：每趟把一个极值 冒 到正确位置，已经就位的后缀（或前缀）以后不再改动

所以 基本版 外层跑 $n$ 趟一定就已经足够了，而 优化版 把内层上界缩成 j < i，是因为尾部已经排好，没有必要再比较

f 这个 flag 的含义是：

  • 某一趟 一次交换都没有 → 当前前缀已经 全局有序 → 可以提前结束
  • 这 不会 改变最坏复杂度，只是在 已经有序 / 接近有序 时把 比较次数 压下来

向前冒 是对称的：每趟把当前 最小值 固定到前缀，不变量 换成 前缀已经就位

数学层面

逆序对 与 交换次数

如果你做过有关 相邻交换 的题目，你应该知道这么个结论：

  • 相邻交换变成有序 的次数等于 逆序对的次数

下面简单说一下：

定义一对下标 $i < j$，若 $a_i > a_j$，就叫一个 逆序对

冒泡 每次只交换 相邻且逆序 的一对：

  • 交换之后，这一对不再是逆序
  • 其它对的相对顺序不变
  • 所以 每一次相邻交换，逆序数恰好减 $1$

于是有一条明确的结论：

冒泡排序的 交换次数 $=$ 输入序列的 逆序数

这和具体是 向前冒 还是 向后冒、有没有缩小边界 无关，只要做的是 相邻交换 来 消去逆序

期望交换次数

假设输入是 $1 \sim n$ 的 均匀随机 排列

对任意一对位置 $(i,j)$（$i < j$），$a_i$ 与 $a_j$ 谁大谁小等可能，所以它是 逆序 的 概率 是 $\dfrac{1}{2}$

一共有 $\dbinom{n}{2}$ 对，用 期望的线性 性质：

$$ \mathbb{E}[\text{交换次数}] = \mathbb{E}[\text{逆序数}] = \binom{n}{2}\cdot\frac{1}{2} = \frac{n(n-1)}{4} $$

所以 平均时间复杂度 也是 $\Theta(n^2)$，并不是 平均能达到 $O(n\log n)$

比较次数 和 交换次数

  • 交换次数：就是 逆序数，跟 early-stop 无关（有序时逆序为 $0$，本来就不交换）
  • 比较次数：取决于 具体实现
    • naive：大约 $n(n-1)$ 量级
    • 带 flag：最好情况下 $n-1$ 次比较就可以结束，最坏仍是 $\Theta(n^2)$

和 插入排序 对照

插入排序 把当前元素 往左插入 时，本质上也是在 消去逆序：

  • 其 不变量 为：第 $i$ 轮进来时 $[0,i)$ 有序，出去时 $[0,i]$ 有序
  • 元素左移的总次数 $=$ 逆序数
  • 随机排列下，期望移动次数同样是 $\dfrac{n(n-1)}{4}$

所以 平均平方级 不是 冒泡 这个操作单独导致的结论，而是 只靠相邻位置修正顺序 这一类算法共有的特点

相邻交换的下界

若排序只允许 相邻交换，要把每个元素挪到目标位置，总交换次数至少是 逆序数

随机排列的期望逆序就是 $\dfrac{n(n-1)}{4}$，因此这类算法平均至少需要 $\Omega(n^2)$ 次交换

想要平均 $O(n\log n)$，必须允许 非相邻 的信息流动，例如 快速排序、堆排序、归并排序

变体：相邻交换的其他写法

冒泡 还有不少相关变体，核心仍然是让 乱序 变成 有序，差别主要在 方向 和 步长

鸡尾酒排序（双向冒泡）

经典单向冒泡会有 兔子 / 乌龟 问题，方向不同，快慢角色也不同：

  • 向后冒（从左往右扫）：大元素 一趟可以连续往后走很远（rabbit），小元素 卡在尾部时一趟只能往前挪一格（turtle）
  • 向前冒（从右往左扫）：正好反过来，小元素 一趟可以连续往前走很远，大元素 卡在头部时一趟只能往后挪一格

鸡尾酒排序 一趟里 先 向后冒、再 向前冒，双向扫，两边的乌龟都能被加速：

void cocktail_sort(std::vector<int>& a) {
    int n = a.size();
    int L = 0, R = n - 1;
    while (L < R) {
        bool f = 0;
        for (int j = L; j < R; ++j) {
            if (a[j] > a[j + 1]) {
                std::swap(a[j], a[j + 1]);
                f = 1;
            }
        }
        --R;
        for (int j = R; j > L; --j) {
            if (a[j] < a[j - 1]) {
                std::swap(a[j], a[j - 1]);
                f = 1;
            }
        }
        ++L;
        if (!f) break;
    }
}

最坏时间复杂度仍是 $O(n^2)$，但对小元素压在右边 或 大元素压在左边 这类单向乌龟输入会更合适一些

梳排序（Comb sort）

把 冒泡 的间隔从 $1$ 拉大，再逐步缩小回 $1$，思路类似 Shell 排序 对 插入排序 的 推广：

  • 用较大的 gap 先消去 远距离逆序
  • gap 缩小到 $1$ 时，退化成 普通冒泡（常常再配合 early-stop）
void comb_sort(std::vector<int>& a) {
    int n = a.size();
    int gap = n;
    bool f = 1;
    while (gap > 1 || f) {
        gap = std::max(1, gap * 10 / 13); // 常见收缩因子
        f = 0;
        for (int i = 0; i + gap < n; ++i) {
            if (a[i] > a[i + gap]) {
                std::swap(a[i], a[i + gap]);
                f = 1;
            }
        }
    }
}

实践中通常会比不加间隔的冒泡更快一些，但 不保证 稳定，最坏情况仍然可能很差

这些变体说明：

  • 冒泡 不是一个死板的 双重循环，而是一族 局部交换 → 全局有序 的算法

硬件层面

串行冒泡

一趟向后冒里，j 和 j+1 比较完、可能交换之后，才会影响下一对 j+1 和 j+2

这是一条 长依赖链：同一趟内部很难把 所有相邻对 同时交给 多核 / SIMD

相邻访问对 cache 其实比较友好，但 $O(n^2)$ 的工作量太大，硬件上的局部友好 无法降低整体复杂度

奇偶排序 / Brick sort

把 相邻交换 改成 两相位交替：

  1. 奇相位：比较并交换 $(1,2),\ (3,4),\ (5,6),\ \ldots$
  2. 偶相位：比较并交换 $(0,1),\ (2,3),\ (4,5),\ \ldots$

同一相位里，这些配对 互不重叠，可以同时做

void odd_even_sort(std::vector<int>& a) {
    int n = a.size();
    bool f = 0;
    while (!f) {
        f = 1;
        for (int i = 1; i + 1 < n; i += 2) { // 奇相位
            if (a[i] > a[i + 1]) {
                std::swap(a[i], a[i + 1]);
                f = 0;
            }
        }
        for (int i = 0; i + 1 < n; i += 2) { // 偶相位
            if (a[i] > a[i + 1]) {
                std::swap(a[i], a[i + 1]);
                f = 0;
            }
        }
    }
}

串行执行 时时间复杂度仍是 $O(n^2)$

但它是 GPU / 多线程上很经典的 教学用并行排序：每个相位做一轮 并行 compare-exchange，大约 $O(n)$ 个相位就足够

FPGA：流水线、计分板、分组比较

软件 里的冒泡是 比较一对、交换、再比较下一对

放到 FPGA 上，如果一个时钟里把 所有交换串 成一条 组合逻辑，路径太长，时序会变差，如果 每个时钟 只交换一对，流水线又要拉到 $O(n^2)$ 级

所以硬件上通常不按这个 双重循环 原样实现

流水线

还是做 相邻交换，但用上面的 奇偶相位，把 没有依赖 的比较放到 同一级：

  • 每一级 是一批 互不重叠 的 比较交换单元
  • 奇相位 一级、偶相位 一级，交替接下去
  • 级 与 级 之间打 寄存器
  • $n$ 个数大约 $n$ 级就够

流水线 填满之后，每个时钟 可以送入 下一组数据

延迟是 流水线级数，吞吐按 时钟 算，不再是软件里那条 一对做完才能做下一对 的依赖链

计分板

另一条路是 只比较、不交换，每个数 和 其它所有数 比一次，比较结果用 1 bit 记下来，再 按行加总，加出来的和就是这个数的 名次，这张表就是 计分板

要注意的是这个 比较 是可以 并行的

相等时 名次 不能撞在一起，否则 两个数 会写到 同一个输出位置，常见规则是：和 下标更小 的数比用 $\ge$，和 下标更大 的数比用 $>$

例如三个数 $3,1,2$，下标分别是 $0,1,2$：

元素 和 3 比 和 1 比 和 2 比 得分
3（下标 0） 1 1 2
1（下标 1） 0 0 0
2（下标 2） 0 1 1

得分就是 输出下标：$1$ 放到位置 $0$，$2$ 放到位置 $1$，$3$ 放到位置 $2$

全并行 时 比较器数量 是 $\Theta(n^2)$，但 数据通路 可以收成大约 三级流水：

  1. 并行比较，记下 1 bit 结果
  2. 按行求和，得到名次
  3. 按 名次 写到 输出寄存器

分组比较

$n^2$ 个 比较器 一次铺开会很占面积，分组比较 是 复用同一批比较器：

  • 数据 先放进寄存器
  • 每拍只拿出一组，和 全部数据 比较，累加得分
  • 例如 32 个数分成 4 组，每组 8 个，4 拍比完，再按 得分 放置

比较器 从 $32 \times 32$ 降到 $8 \times 32$，代价是 时钟周期变多

组数 可以按 面积 和 延迟 再去调整，这是 面积 和 延迟 的 折中

结语

冒泡排序 表面上是 两层循环，拆开来看的话至少有这些 层面：

层面 总结
正确性 每趟固定一个 极值，不变量 保证可以 提前结束
数学 交换次数 $=$ 逆序数，期望 $\dfrac{n(n-1)}{4}$
变体 鸡尾酒 排序改 方向，梳排序 改 步长
硬件 串行 有 长依赖链，奇偶相位 可以 并行，FPGA 上常用 流水线、计分板 和 分组比较

所以关键不在于它慢，而在于如果只记住一个 $O(n^2)$，就会错过后面这些 结构
