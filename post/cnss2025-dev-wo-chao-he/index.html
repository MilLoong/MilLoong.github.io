❓一些思考

小提一嘴 邮箱变成链接了有点难复制（）

  • 题目的问题有几个关键的信息，“通用的类”，“新建或注册类”，“序列化或反序列化

  • 我刚开始做的时候光看到**“新建或注册类”了，猜想也许大概应该可能是写个“交互”？于是就先写了个命令行交互，然后无聊调了个 GUI 的库先写的在 GUI 上交互qwq ，但很显然这是有点难办的（或者办不了？反正我在网上找不到解决方法= =），然后我做的时候也是乱搞了一些 定义和注册数据类型 ，定义和注册类 之类的函数，所以就搞了个用户可以在交互界面上输入类名，输入字段名之类的（当然这个字段是定义或者注册好的），最后觉得有点奇怪，然后就看到”通用的类“**了，所以我就这么翻译题目：

    • “新建”：

      • 指在代码里新建，也就是编译时类型和变量名什么的都是确定的

    • “注册”：

      • 同新建，应是编译时确定

      感觉题目应该是这个意思吧，不然感觉真做不了😰

  • 既然是在编译时确定的话就好办了，可以用一些比如类模板，类型工厂来做得更通用一些

  • 至于怎么序列化，由于不能调第三方库，我就自己想了一个比较简单的序列化策略：

    • 魔数：
      • 给每个序列化字符串最前面加上一个版本号的魔数，当然这里只是魔数验证的一个思路，好像这题没叫做类型验证，但我还是写一下（
    • 分隔符：
      • 这个分隔符可以随便取，我这里取了一个逗号 , 然后就用一个简单的 getline 来根据逗号分隔
      • 不过如果是字符串的话会卡这个 getline 所以为了安全，直接在字符串前面加上它的长度作为前缀，以 : 来标明，所以就类似 <len>:<string> 的格式
      • 至于其他类型，由于读入的是字符串，所以其他类型可以用一些 api 来转换就好了，比如int，就可以用 stoi 转换（当然手写类型转换也可以，我这里就直接用 api 了qwq），然后就不会卡 , 了
      • 如果是数组或一些容器，先打印元素个数 <count>:，然后再用上面的规则输出元素
      • 如果是类（嵌套对象），则递归调用该对象的 serialize 方法，将其结果作为一个独立的字符串，同样采用 <len>:<string> 的格式嵌入到当前数据流中。这样可以就可以支持任意深度的对象嵌套了
      • 其他一些类型我暂时没考虑，不过应该是没问题的
    • 保存文件：
      • 序列化后的内容以二进制的形式保存在 .dat 文件

  • 那反序列化就是反过来了，这里不多赘述

✍🏻Code

  • 代码太长了我就不放在文档里了，放在当前目录下的 serializar.cpp ，这里主要说一些跟运行和代码设计的东西：

    • 运行：

      • 我有写 makefile，用：

        make run

        编译并运行

      • 运行环境的话，没有用什么库，然后在 Linux 或者 Windows 都可以运行，有 gcc/g++ 就好（我用的 C++17。当然，还要有 cmake 来运行 makefile

    • 序列化接口：

      • 我这里定义了一个序列化接口：

        • //序列化接口

class Serializable{

public:

    virtual ~Serializable()=default;

    virtual std::string serialize()const=0;

    virtual void deserialize(const std::string&data)=0;

    virtual std::string getTypeName()const=0;

};

        • 如果说要新建类，就可以继承这个接口，并实现接口的所有虚方法

          至于一些 serialize/deserialize 怎么写，这里的话由于每个类确实是不同的，不好写一个通用的方法，所以我就写在继承这个接口的类里了，详情可以看一下测试样例

    • 序列化系统工具类：

      • 顾名思义，用来控制注册类，序列化写入文件，反序列化到程序的

    • 测试样例：

修订

关于序列化方式

  • 确实，二进制流就不用管分隔符和定长数据结构了，之前确实没想过，因为确实想想出一些策略，所以我在新的代码里也是直接改了（

  • 关于多类型的对象到同一个文件

    • 这个不难实现，我在 SerializaionSystem 里加了个 serializeMultipleToFile ，序列化的时候对应逻辑就是获取类型名后调用相应的 serialize ，反序列化就是相反的了

  • 关于码风

    • 这确实是我个人码风的问题，我还是比较喜欢简洁一点的（），所以如果有点难受的话那我就直接格式化文档了（

  • 关于代码修改部分

    • 现在我把原来的多类型到多文件，边界数据封装到了对应的函数，然后又新加了一个多类型到单文件的函数来实现新增的任务，而且注释添加得详细了一些，因为之前发的那个好像没有调试输出说序列化成功之类的（关于调试，我是喜欢用英文来输出调试输出的）
    • 然后主程序里我是把前两者注释掉了，也就是说新的这个程序只会输出多类型到单文件的测试内容，如果前面两个也要看的话，那就在主程序把对应的函数注释去掉就好
