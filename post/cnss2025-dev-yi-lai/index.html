🧪 依赖这一块

CH1

  • 什么是数据依赖？一般分为哪些类型？

    • 什么是 数据依赖 ？

      这里应该显然是 编译原理 中的定义，所以涉及其他领域的应该不用写（

      • 数据依赖

        • 是指一种状态，当 程序结构 导致 数据 引用之前 处理过的数据 时的状态

        • 具体来说，

        • 如果两个 存储访问 操作访问 同一个变量，其中一个访问是写（或更新）操作，则两个操作间存在 数据依赖

        • 数据依赖关系 体现了两个 存储访问操作 的 执行顺序，必须按照该顺序执行两个操作才能得到正确的结果

          比如：

          a = b + c;

d = 2 * a;

        • 在 编译原理 中，数据依赖 是 数据分析 的一部分，是 数据流 之间的一种依赖

    • 数据依赖 分为 哪些类型？

      • 流依赖：

        • 一个 变量 在一次表达式中 被赋值或修改 然后 被使用 在后来的另一个表达式中

        • 比如：

          a=b+c

...

d=a-e

      • 反依赖：

        • 就是 流依赖 反过来

        • 一个 变量 在一次表达式中 被使用 然后在后来的另一个表达式 被修改或修改 中

        • 比如：

          c=a+b

...

a=b*e

      • 输入依赖：

        • 即 被使用 多次

        • 一个 变量 在一表达式中 被使用 然后又在后来另一个表达式中 被使用

        • 比如：

          b=a+c

...

d=a*e

        • 不过注意到这种 依赖 没有约束 语句的执行顺序，所以好像有些书归进 数据依赖 的类型（比如 鲸书，有说过：“严格来讲，这是第四种 数据依赖 类型”），而有些书没有归进（比如 龙书）？不过我觉得这里还是归进吧（

      • 输出依赖：

        • 即 被赋值 多次

        • 一个 变量 在一表达式中 被赋值 然后又在后来另一个表达式中 被赋值

        • 比如：

          a=b+c

...

a=d*e

  • 下面这个循环可以并行吗？为什么？

    for(int i = 1; i<= 100; i++) {

  for(int j = i; j <= 100; j++)

    A[i][j + 1] = A[100][j]

}

    • 首先理论上，只要有上面所说的 前三种数据依赖，循环 就不能并行

      也就是不能有：

      • 读后写
      • 写后读
      • 写后写

      那就只需看看是否存在 A[i][j] 会出现上面 三种情况 的其中 一种 就好了

      • 这里可以观察一下 等号 右边的 A[100][j]，显然 A[100][j] 不会被写

        事实上，假设 A[100][j] 会被写，首先 j <= 100 。然后由于 i = 100，所以 j 从 100 开始枚举，等号 左边就只能是 A[100][101]，与 j <= 100 并不重叠，所以矛盾

        那么 A[100][j] 就只会被 读，不会出现上述 三种情况

      • 而在 等号 右边 的只有 A[100][j]，所以 读后写、写后读 不会出现，只需考虑 A[1...99][j] 有没有可能出现 写后写，也就是 被赋值 两次

        这个也是很显然的，每次迭代中的 i 都不一样，所以 A[i][j] 自然不会出现 写后写

    • 综上，这个循环可以并行

  • 在什么条件下循环可以安全地并行执行？

    • 不存在循环携带的数据依赖

      • 上面好像说过一点，我直接 copy 下来吧（

        首先理论上，只要有上面所说的 前三种数据依赖，循环 就不能并行

        也就是不能有：

        • 读后写
        • 写后读
        • 写后写

        那么 循环 可以安全地并行执行，就是要：

        • 没有上面说的 三种数据依赖
        • 可以有 输入依赖

        也就是说，不存在循环携带的数据依赖

    • 不存在循环携带的控制依赖

      • 控制依赖 是 程序控制流 导致的一种约束，详细的过程这里就不说了，好像不涉及

      • 如果在 循环 中涉及 循环携带的控制程序，那么是不好判断是否能并行的，而且一次 迭代 的执行 决定 了另一次 迭代 的执行了

      • 比如：

        for (int i = 0; i < 100; i++) {

    if (a[i] < 0) {

        break;

    }

    // ...

}

      • 所以要安全地并行执行，是不能有 循环携带的控制依赖 的

    • 不存在循环携带的地址依赖

      地址依赖（address dependence）这个词好像我没怎么能搜到，也忘记在哪本书看到了，不过好像确实有这个东西，我觉得也是原因之一吧，所以加了进来（

      • 地址依赖 和 数据依赖 很像，就是 访问的地址 要在上一次计算出来，比如：

        r1 = r2 + r3        

r4 = mem[r1]

      • 那显然 循环携带的地址依赖，也是不能够让 循环 安全地并行的，这个例子只要用 嵌套数组 来说明一下就好了：

        for (i = 1; i < n; i++) {

    A[B[i-1]] = A[B[i]] + 1;

}

        这里显然第 i 次迭代的时候，需要用到第 i+1 次迭代的数据

        不过这个例子好像也可以用 数据依赖 来解释？

CH3

  • CH1 和 CH2 有什么关系？

    • 判断是否有 数据依赖，可以通过 CH2 中的 整数约束求解工具 来处理

      • 判断是否有 数据依赖，即 判断两个数组访问在 不同迭代 中是否可能访问 同一内存位置

      • 比如：

        for (int i = 0; i < n; i++)

    A[i + 1] = A[i];

        对应的 约束系统是：

        i + 1 = j           

0 ≤ i < n          

0 ≤ j < n          

i ≠ j

        而其存在整数解 i=0,j=1，则存在依赖

    • 在 循环嵌套 进行了 循环交换变换 以后，需要重新计算各个层级 循环变量 的上下界，而在 多面体编译 领域要求更严格的 循环变量 的约束形式，即要写成 更外层循环变量 的 仿射表达式 形式，这时候就需要 CH2 中写的 整数约束求解工具 来进行处理了

  • 你还知道哪些常见的循环变换？它们需要满足哪些条件？

    查了一下，大概有：

    • 改变指令实例执行顺序的变换

      • 仿射循环变换

        • 循环交换

          • 需要满足 依赖向量的方向向量 在交换后仍然是 字典序 正的
          • 不能违反原有的数据依赖关系

        • 循环反转

          • 需要分析反转后 依赖关系 是否仍然合法
          • 依赖距离向量 在反转后需要保持合法方向

        • 循环延展、循环倾斜

          • 需要保证变换后的 迭代空间 仍然是合法的，且 依赖距离向量 满足特定条件
          • 依赖距离向量 满足特定条件（通常用于消除某些方向的依赖）
          • 变换矩阵 必须是可逆的（行列式非零）

        • 循环合并/分布

          • 合并

            • 相邻循环 需要有相同的循环边界，且循环体之间没有依赖冲突

          • 分布

            • 需要保证 分布 后每个循环仍然保持原有的依赖关系

      • 近似仿射循环变换

        • 循环分段

          • 分段后每段 内部 和段与段之间的依赖关系都必须合法

          • 通常用于处理 不规则 的依赖模式

        • 循环分块

          • 需要保证 块内 和 块间 的依赖都是合法的

          • 块的大小需要根据 缓存大小 等特性选择

          • 需要处理 边界情况

        • 循环展开压紧

          • 展开因子 需要与 依赖距离 兼容

          • 需要保证展开后的语句之间没有 依赖冲突

    • 不改变指令实例执行顺序的变换

      • 分块分离
        • 主要考虑 代码大小 和 缓存效率，不需要依赖分析
      • 循环展开
        • 不改变执行顺序，主要考虑：
          • 循环次数 是否已知
          • 代码膨胀 是否可接受
          • 寄存器压力
      • 循环判断外提
        • 需要保证提取出的条件在 循环外计算 是安全的
        • 不能有副作用 或 依赖于循环变量
      • 循环剥离
        • 需要识别出可以 单独处理 的 首尾迭代
        • 不改变 整体执行顺序
      • 循环压紧
        • 主要是 代码优化，需要保证 压紧 后逻辑等价

  • CH2 的整数约束求解工具可以如何应用于并行等循环变换的分析？

    • 调度变换与线性整数规划：

      • 这里主要是在 多面体编译 中的应用（感觉这个应该才是主要的，因为题目感觉就是对着 多面体编译 出的qwq）

      • 调度变换算法就是将调度由一个仿射函数变换为另一个仿射函数，其实际上是在迭代空间上进行基变换的一个过程，本质上是在给定一组约束的条件下，求出最大的目标函数的过程，也即线性整数规划的过程

      • 比如，把：

        for (int i = 0; i <= 5; ++i) {

    for (int j = i; j <= 7; ++j){

        //...

    }

}

        变成：

        for (int j = 0; j <= 7; ++j) {

    for (int i = 0; i <= min(j, 5); ++i){

        //...

    }

}

    • 依赖测试：

      • 如上所说，可以把 判断是否有 数据依赖 转换成 线性约束系统 是否有解

      • 判断两个数组访问 A[f(i)] 和 A[g(j)] 在不同迭代中是否可能访问同一位置

      • 转化为整数约束问题：f(i) = g(j) 且 i, j 满足循环边界条件

      • 如果有整数解，则存在依赖

    • 循环变换合法性验证：

      • 检查 变换 前后 依赖距离向量 是否仍然满足字典序正

      • 这可以转化为一组 线性不等式约束

    • 并行性分析：

      • 这个就和 依赖测试 差不多了

      • 判断循环是否可以并行：

        • 检查是否存在 循环携带依赖

        • 即检查依赖距离向量是否可能为零向量

      • 如果 f(i) = g(j) 且 i ≠ j 无整数解，则说明不存在 循环携带依赖 ，可以并行
