🧠 Brainwash Final

既然是完整的 wp 的话，那我还是直接 copy 第一次交的 .md 吧，然后改动一些地方

❓CH1

  • 思考

    根据 Hint：

    Brainfuck 是图灵完备的。

    所以其实就很明显了，证明题目给的 指令集 可以实现 Brainfuck 的所有功能就好了。

    不过指令集涉及 i^=1 、i^=1<<ctz(i)+1、popcount 的条件分支等操作，如果对 标准二进制 作操作的话，要实现 Brainfuck 中的 <> 和 +- 是会很困难的，并且每次操作的操作序列是不固定的。所以我刚开始的时候按照 标准二进制 来搞，发现其实 i^=1 、i^=1<<ctz(i)+1 这类操作的出现次数不会连着出现两次，所以一直在构造 s 和 z 的交替序列来看有什么性质，不过这样的话就不能用 popcount 了，然后就卡住了（

    接着我就考虑怎么使用 qab 或 pab，也就是涉及 popcount 的操作。这个的话，可以联系一下 i^=1 、i^=1<<ctz(i)+1 这两种操作，这不就是k 位格雷码的构造操作吗？所以想到这题其实是用 格雷码 来做。

    而格雷码有个关于 popcount 的性质：

    • 格雷码任意两个相邻的代码只有一位二进制数不同，也就是说，相邻两项的 popcount 差 1 ，且相邻两项异或起来的值的 popcount=1

    可以打个表来看一下：

    十进制 标准二进制 格雷码 popcount(格雷码)
    0 000 000 0 (偶)
    1 001 001 1 (奇)
    2 010 011 2 (偶)
    3 011 010 1 (奇)
    4 100 110 2 (偶)
    5 101 111 3 (奇)
    6 110 101 2 (偶)
    7 111 100 1 (奇)

    可以看到，初态是 0 的时候：

    • 若 popcount 为偶数，则当前项 +1 就是 ^1，-1 就是 ^1<<ctz(i)+1
    • 若 popcount 为奇数，则当前项 +1 就是 ^1<<ctz(i)+1，-1 就是 ^1

    而这恰好和 qab 与 pab 中的 popcount(i)&1 的判断相匹配，所以这题肯定就是这么写的

    那题目给的指针操作及内存操作都是有 ^1、^1<<ctz(i)+1、判断popcount&1 的操作的，所以两者可以分别实现 <> 和 +- 的

    然后 指针 就用 格雷码 保存了，这没问题

    不过 内存 是用 getchar 作为输入，putchar 作为输出，这两者都是输入或输出 标准二进制 的，要考虑输入以后怎么转换成 格雷码，以及怎么从 格雷码 转换为 标准二进制 来输出。

    这个时候可以利用 mem[i] 有而 i 没有的一些操作来证明了：

    u: mem[i] = mem[mem[i]]

v: mem[i] = mem[mem[i] + 256]

[...]: while (mem[i]) ...

[: if (!mem[i]) goto corresponding ]

]: if (mem[i]) goto corresponding [

    可以看到 u 和 v 是间接寻址，要利用的话，就要 打表

    先找一下规律，发现，其实 u 操作中 索引 的取值范围是 [0,255]，v 操作中 索引 的取值范围是 [256,511]，两者是错开的，互不重叠

    于是我们可以将 [0,255] 当作 binary2gray，[256,511] 当作 gray2binary

    那这个 打表 的话，肯定是在 .bw 来打，也就是说在 正常程序 运行前先执行这个打表代码

    考虑怎么生成这个 打表代码

    既然是在 .bw 打表，而且这个表应该是要打完 [0,511] 的，不然 动态 打的话不能预测 i 输入进来的字符

    那就直接写个 generate.py 来生成 打表 的操作序列

    写这个 生成器 的思路也很简单，对于 binary2gray，直接根据 i 的 格雷码 对应十进制，来决定 mem[i] 加多少

    而 gray2binary 复杂一点，要先求出 i 对应的 binary，然后用一个 binary 和 gray 的对应关系，找到对应的 qzs 序列

    这样就能生成一个 stdlib.bw 的表

    然后的话看起来应该不是每次都要执行这个 表 中的内容，所以就不在程序中自动执行 stdlib.bw 了

    这样， .bw 文件的话每次执行的时候先执行 stdlib.bw 的内容，然后再执行相应的逻辑就好了

    然后我加了一个注释代码的 #，这样便于对 .bw 进行注释

  • 证明

    要证明所给的 Brainwash 可以实现 Brainfuck 的所有功能，其实就是证明 指令集 可以实现 Brainfuck 的 8 条命令：

    字符 含义
    > 指针加一
    < 指针减一
    + 指针所指字节的值加一
    - 指针所指字节的值减一
    . 输出指针所指字节内容（ASCII码）
    , 向指针所指的字节输入内容（ASCII码）
    [ 若指针所指字节的值为零，则向后跳转，跳转到其对应的]的下一个指令处
    ] 若指针所指字节的值不为零，则向前跳转，跳转到其对应的[的下一个指令处

    • [，]

      先从最简单的入手，因为题目已经说了：

      • [] 和 Brainfuck 中的 [] 含义完全一致，括号是允许嵌套的。

      所以就不难证明其能完成 Brainfuck 的 [] 功能了

    • <，>

      Brainwash 中涉及 当前指针 移动的操作有：

      x: i ^= 1

y: i ^= 1 << ctz(i) + 1

qab: if (popcount(i) & 1) a else b

      根据 思考 得知，popcount(i) 是奇数时，当前指针 +1 就是 ^1<<ctz(i)+1，-1 就是 ^1，偶数反之，所以 < 的 Brainwash 表示是：

      qxy

      > 的 Brainwash 表示是：

      qyx

    • +，-

      Brainwash 中涉及 内存 加减的操作有：

      s: mem[i] ^= 1

z: mem[i] ^= 1 << min(ctz(mem[i]) + 1, 7)

pab: if (popcount(mem[i]) & 1) a else b

      那么就和 <，> 的处理同理，+ 的 Brainwash 表示是：

      pzs

      - 的 Brainwash 表示是：

      psz

    • ,，.

      如 思考 中所说，我们先执行 stdlib.bw 的打表指令，然后就能够用

      • u：binary2gray
      • v：gray2binary

      对于 ,：

      • i 输入进来的是 binary，并且会对 mem[i] 进行覆盖，所以在 i 之后直接执行 u 就好了，所以是：

        iu

      对于 .：

      • o 要先用 u 把 mem[i] 的 格雷码 转换为 bianry，然后输出之后，还要用 v 转回去，所以是：

        vou

    所以这样我们就证明了 Brainwash 能实现 Brainfuck ，对应的 Brainfuck 命令与 Brainwash 等价实现 的关系是：

    Brainfuck 指令 Brainwash 等价实现
    + pzs
    - psz
    > qyx
    < qxy
    . vou
    , iu
    [ [
    ] ]

    于是就能证明 Brainwash 是 图灵完备 的了

      • JIT 简要设计思路

        既然题目说要简要说一下 JIT 的设计思路，那这里虽然是用的开源项目，我还是说一下吧

        首先我们知道，JIT 是在 运行时 将一部分代码动态地编译成机器码，而不是整个代码都编译成机器码，然后程序就直接跳转到这段 机器码 上执行，就会比逐条指令放到 解释器 中快，也不像 AOT 那样复杂

        而其需要向 内存 中申请一块可读、可写、可执行（RWX）的内存区域，用于存放动态生成的机器码

        然后通过维护 CPU 寄存器（如 rdi 或 rbx）始终指向 Brainwash 的"纸带"内存的当前单元格，这样，对指针的操作就变成了对这个寄存器的简单加减操作（如inc rdi, dec rdi）

        然后对于 I/O 操作，需要调用外部的 getchar 和 putchar，这个不难实现，用 extern 就行

        然后是 [] 这种跳转命令，确实也是一个难点，需要预留跳转地址的空位，在后续生成回跳的机器码时计算偏移量，并将其填入原先预留的空位中，并且要注意字节序等

        关于 汇编代码 的处理：

        • 使用 dynasm-rs 这个库来编写 x86-64 汇编指令

        关于 地址指针：

        • **内存指针 (rdi)：**内部的数据指针 (data_ptr)
        • **内存基地址 (rbx)：**用 rbx 寄存器保存了 mem 数组的基地址，以此来计算 偏移量

        各个 指令 翻译成 汇编：

        • s(mem[i] ^= 1)：

          • 直接翻译成 xor BYTE [rdi], 1。其中[rdi] 表示 rdi 寄存器中地址所指向的内存位置，BYTE 表明操作单位是一个字节

        • x(i ^= 1)：

          • i 的值通过 rdi - rbx 得到。所以先计算出偏移量 rax = rdi - rbx，然后 xor rax, 1，最后再将新的地址写回 rdi（rdi = rbx + rax）

        • z 和 y：

          • 这两个指令需要计算 ctz，这在汇编中没有直接对应的指令
          • 所以要调用外部 Rust 函数 extern_ctz 和 extern_ctz_u32 来完成计算
          • 先 movzx rcx, BYTE [rdi] 准备参数，然后 call rax 调用函数，最后利用返回值完成后续的位移和异或操作

        • i / o：

          • 输入 I：

            call extern_getchar … mov BYTE [rdi], al

            
即先获取字符，再存入内存

          • 输出 O：

            movzx rcx, BYTE [rdi] … call extern_putchar

            
即先从内存加载格雷码，再调用打印函数

        • u(mem[i] = mem[mem[i]])：

          • 先用movzx rax, BYTE [rdi] 读取 mem[i] 的值（地址偏移），然后 add rax, rbx 将其转换成绝对地址

            mov al, BYTE [rax] 再从这个新地址读取数据，最后 mov BYTE [rdi], al 写回

        • p / q:

          • 调用外部 popcount 函数

        • 准备参数、调用函数，然后 and eax, 1 和 cmp eax, 0 检查返回值的奇偶性，最后使用 je 条件跳转指令 来选择执行 a 分支还是 b 分支的代码

          • 我这里是写了个辅助函数 compile_single_instruction 来生成分支内的代码

        • **JIZ / JNZ **:

          • 首先为每个 IR 指令创建了一个动态标签 labels[i]
          • 然后 JIZ 指令被编译为 cmp BYTE [rdi], 0 和 jz =>labels[*target_idx]
          • JNZ 同理

        • dynasm 在最后链接阶段把这些标签解析成正确的跳转地址

    • 主要文件说明：

      • src/Interpreter.rs：Brainwash 解释器核心逻辑
      • src/jit_compiler.rs：JIT 编译器实现
      • src/ir.rs：中间表示定义与优化
      • src/opcode.rs：操作码与指令集定义
      • src/main.rs：命令行参数解析与程序入口
