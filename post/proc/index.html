深入理解 Linux 中的 proc 目录

前言

众所周知，Linux 的 理念 是：

  • 万物皆文件

那到底该怎么理解这个理念？为什么 万物皆文件？

而要理解这个理念，其中比较重要的部分就是这个 proc 目录，本文将深入探讨这个 proc 目录到底是什么，以及有什么用

定义

proc 是 Linux 中的一个 VFS（虚拟文件系统），挂载点通常是 /proc，用于暴露 内核 在 运行时 的 数据结构 和 进程信息

原英文定义为：

The proc file system acts as an interface to internal data structures in the kernel. It can be used to obtain information about the system and to change certain kernel parameters at runtime (sysctl).

需要注意的是，proc 不存放在磁盘上，而是由 内核 在 内存 中 动态生成

这就可以让我们 实时获取 运行时 的信息，比如某个 进程 的相关信息，或者说 驱动信息、网卡信息

内容

一般来讲，/proc 下的内容会由于 内核配置 和 装载的模块 等有所不同，但通常包含以下几类：

  • 进程信息
  • 系统全局信息文件
  • 内核可配置参数文件

进程信息文件

一般 目录名 为 数字，对应 进程 PID，里面包含该进程 运行时 的 状态信息

  • cmdline

    • 可以看 启动进程 时的 命令行参数（参数之间在文件里是 \0 分隔，cat 时可能连在一起显示）

    • 比如：

      root@root:/proc/1$ cat cmdline
/sbin/init

    • 这里表示启动该进程时，命令行里带有 /sbin/init

系统全局信息文件

一般包括 伙伴系统信息、CPU 信息、内存信息、系统平均负载、内核版本

  • buddyinfo

    • 每个 内存区 的每个 order 有多少 空闲块 可用，即 free_area[order].nr_free，是 伙伴系统 的信息，和 内存碎片问题 有关

    • 比如：

      root@root:/proc$ cat buddyinfo
Node 0, zone    DMA32      1      1      1      0      0      2      2      1      1      3    973
Node 0, zone   Normal    652    318    567    605    252    216    136     91     40     55    656

    • 拿第一行举例，依次代表如下：

      NUMA 节点 0  这个内存区         free_area[0] free_area[1]
Node 0,     zone    DMA32      1            1...

  • cpuinfo

    • 包含 CPU 的 信息，比如 CPU 型号、厂商、核心数、频率、缓存大小 等

    • 比如我想获取 当前 CPU 的逻辑 CPU 数：

      root@root:/proc$ cat cpuinfo | grep 'processor'

processor       : 13
processor       : 14
processor       : 15

  • meminfo

    • 这个文件详细展示了 系统内存 的 使用情况，包括 总内存（MemTotal）、空闲内存（MemFree）、估算可用内存（MemAvailable）、缓冲区（Buffers）、页缓存（Cached） 等

    • MemAvailable 是内核估算的 启动新应用 而不易触发 swap 的可用量，会把可回收的 cache / buffer 等算进去，不是 MemTotal - MemFree

    • 比如我想查上面说到的信息：

      root@root:/proc$ grep -E 'MemTotal|MemFree|MemAvailable|Buffers|Cached' meminfo
MemTotal:        7967328 kB
MemFree:         6990648 kB
MemAvailable:    7081144 kB
Buffers:           14808 kB
Cached:           210688 kB
SwapCached:            0 kB

  • loadavg

    • 即 系统平均负载，记录了 过去 1 分钟、5 分钟、15 分钟 的 系统平均负载情况

    • 平均负载 是指 系统 在 某个时间段 内，处于 可运行 或 不可中断 的 平均进程数

    • 一般来说，如果 平均负载 持续高于 CPU 核心数，说明 系统负载 较重，可能存在 性能瓶颈，所以 系统平均负载 常用来在 高并发 Web 服务器 环境中 监控 服务器 是否处于 过载 状态

    • 比如：

      root@root:/proc$ cat loadavg
0.02 0.03 0.00 1/310 2602
      值 含义
      0.02 最近 1 分钟 平均负载
      0.03 最近 5 分钟 平均负载
      0.00 最近 15 分钟 平均负载
      1/310 分子：当前 可运行调度实体（R 状态 + D 不可中断睡眠）数量分母：系统 全部调度实体 总数（进程 + 线程）
      2602 最近 新创建 的 进程 PID

  • version

    • 即 内核版本，包括内核的 主版本号、次版本号、修订版本号、编译信息 等

    • 比如：

      root@root:/proc$ cat version
Linux version 6.18.40.1-microsoft-standard-WSL2 (root@71c659030f6c) (gcc (GCC) 13.2.0, GNU ld (GNU Binutils) 2.41) #1 SMP PREEMPT_DYNAMIC Fri Jul 31 22:12:15 UTC 2026

内核可配置参数文件

这个就是 可以在 运行时 更改的 内核参数，在 /proc/sys 目录下

  • net
    • 网络参数 相关，比如 ipv4、ipv6
    • 比如：
      • /proc/sys/net/ipv4/ip_forward 控制 IP 是否转发
      • /proc/sys/net/core/somaxconn 限制 全连接队列 的 上限
  • vm
    • 内存管理参数 相关，比如 swap
    • 比如：
      • /proc/sys/vm/swappiness 表示系统将 内存数据 交换到 磁盘交换空间（swap） 的 倾向程度，取值范围是 0 - 100
  • fs
    • 文件系统相关参数，比如 文件描述符上限
    • 比如：
      • /proc/sys/fs/file-max 定义了 系统级别的 文件描述符上限

需要注意的是，直接改 /proc/sys/... 的值，在 系统重启 之后会恢复成默认值

如果想要永久应用，需要将参数配置写入 /etc/sysctl.conf 或 /etc/sysctl.d/，然后执行 sysctl -p 使配置生效

proc 文件的应用

系统性能监控

比如可以利用 /proc/stat 中和 cpu 相关的信息，从而检查 CPU 各个状态 的 时间占比，再进行对应的优化：

root@root:/proc$ cat stat | grep 'cpu '
cpu  7894 699 6660 14777967 1795 0 1774 0 0 0
字段名 值 含义
user 7894 普通 用户态 进程 运行时间（nice>0 除外，业务代码、应用程序）
nice 699 低优先级 用户态进程的 运行时间（nice 值为正数，调低优先级的进程）
system 6660 内核态 耗时：系统调用、内核代码执行
idle 14777967 空闲时间，CPU 无事可做
iowait 1795 CPU 空闲，但是在 等待 IO 完成（磁盘 IO 瓶颈看这个）
irq 0 硬件中断 耗时（网卡、磁盘控制器硬件中断）
softirq 1774 软中断 耗时（网络协议栈、定时器等内核软中断）
steal 0 虚拟化环境，宿主机 抢占走的 CPU 时间，物理机一般是 0
guest 0 KVM 虚拟机客户机 占用 CPU 时间
guest_nice 0 带 nice 调整 的 虚拟机客户机时间

故障排查

当 进程异常（卡住、即将崩溃、收到异常信号等）时：

  • 可以用 /proc/[PID]/status 查看 进程 的 状态、信号 等信息

    • 比如看 信号队列 使用情况、当前 未处理的 信号，判断异常是否与信号有关
    • 注意：进程一旦彻底退出，对应的 /proc/[PID] 目录也会消失

  • 如果启用了 核心转储（core dump），崩溃后内核会按 kernel.core_pattern 把 快照 写到磁盘上的 core 文件（或交给 systemd-coredump 等），再用 调试器 分析 调用栈

    • 进程存活时，/proc/[PID]/coredump_filter 只决定 转储 时包含哪些 内存段，它本身 不是 可供 gdb 直接加载的 转储文件

    • 比如用 gdb 加载 可执行文件 和 磁盘上的 core：

      gdb a.out core
# 或
gdb a.out /var/lib/systemd/coredump/core.....

    • 然后用 bt 来看 调用链

如果想要查看 TCP 连接 的信息：

  • 可以用 /proc/net/tcp 查看 TCP 连接 的 状态信息

    • 其中第 4 列 st 是 连接状态（十六进制）

    • 比如用 awk 统计 不同连接状态 的 个数：

      awk 'NR>1 {print $4}' /proc/net/tcp | sort | uniq -c
