你是如何处理输入输出重定向的？

当然只是简单实现题目说的 < 和 > ，对于 << 和 >> 暂时先不做处理

  • 在分词阶段把重定向符号 <、> 识别为独立token。

    由于要和管道一起处理，所以我弄了个 process 链表（维护 infile 和 outfile）来表示一段管道的运行节点

    然后识别完重定向符号后就在每个process上遍历argv（argv[0]是程序名，其余元素是参数，最后以NULL结尾）：

    • 遇到 > 打开目标文件为 O_WRONLY(只写)、O_CREAT(若不存在就创建)、O_TRUNC(覆盖写) 并记录到 process->outfile

    • 遇到 < 则以 O_RDONLY 打开并记录到 process->infile

      随后将这两个 token（符号与文件名）从 argv 中移除。

      执行时在子进程内用 dup2(process->infile, STDIN_FILENO) 与 dup2(process->outfile, STDOUT_FILENO) 完成重定向(dup2的作用就是将 infile/outfile 绑定到 stdin/stdout)，然后 execvp。

      对于有管道的情况，若未显式设置重定向，则由 管道 读端或写端 填充 infile/outfile。

你是如何实现作业控制的？

  • 为每条命令构建 job 与 process 链表。
  • fork（创建子程序） 以后就用 setpgid 把 job 的所有子进程放入同一进程组，并以一个 job->job_id 作为作业标识，并在前台运行时用 tcsetpgrp 把终端前台组交给该进程组。
  • 使用 SIGCHLD 信号处理器，使用 waitpid(-1, ..., WNOHANG(非阻塞等待)|WUNTRACED(也报告被停止)|WCONTINUED(也报告先前停止后又被继续)) 更新每个 process 的 completed/stopped/status 状态。
  • 维护作业链表，实现前台和后台切换。
  • 内建命令：
    • jobs 遍历作业列出状态
    • fg 将目标进程组设为前台、如有必要会 SIGCONT，并调用 wait_for_job 阻塞直到前台作业完成或停止
    • bg 切后台并 SIGCONT 继续。后台启动（命令尾带 &）仅启动不等待，并打印作业号。

实现中哪里比较困难？

  • 分词器需要同时处理引号、转义与分隔符（| < > &）：

    • 有可能把分隔符错误进入普通参数
    • 有可能出现输出污染或重定向异常。

  • 管道与重定向的交互：

    • 需要在构建 process 链表时正确设置 infile/outfile（管道为默认 IO，而重定向为优先覆盖），并在父进程中及时关闭不再需要的管道端，这样才能避免 fd 泄漏导致 下游进程 读不到 EOF（这里卡得，有点久）。

  • 作业控制与终端控制：

    • 正确设置进程组、切换前台控制终端、在前后台切换时配合 SIGCONT，以及通过 SIGCHLD/waitpid 来准确维护进程状态，防止出现僵尸进程等问题。

  • 内存问题：

    • 老生长谈了，不多赘述，反正要注意某些步骤的内存泄漏等内存问题。

  • Line Editor：

    • 本来还是想自己实现的qwq，发现还是有些复杂，所以在 basis 版本就用的getline，但显然用getline不能处理 bonus 部分，所以后面找了好久的 Line Editor 有关的库（具体看 bonus 部分）

用户配置

  • 可以创建一个.mini_shellrc 配置文件来使用

    这里说一下， .mini_shellrc 文件是可以指定目录的，只要用：

    make CONFIG_PATH="<path_name>/.mini_shellrc"

    就好了。

    不过如果没有指定的话，直接：

    make

    就是在当前目录（bonus 文件夹）下找 .mini_shellrc 文件

    在当前目录下我已经留了一个示例 .mini_shellrc 文件，内容是：

    -- 清空旧配置
clear_aliases()
clear_completions()

-- 设置提示符
set_prompt("[mini-shell]%CWD%BRANCH$ ")

-- 设置全局标志
set_flag("COLORIZE", 1)
set_flag("SHOW_GIT", 1)

-- 设置别名
set_alias("lll", "ls -l")

-- 设置补全规则
set_completion("git", {"fetch", "merge", "clone"})

-- 设置颜色
set_color("command", "blue")
set_color("option", "cyan")
set_color("special", "yellow")
set_color("string", "magenta")

-- 设置历史最大条数
set_history_max(50)

    不过我并没有设置自动创建文件，所以如果对应地方没有 .mini_shellrc 文件的话，是会在运行时报错的（当然一些路径没输对等非法情况也会报错）。

  • 补全配置和高亮配置上面说了

  • 命令提示符配置就是在 .mini_shellrc 中：

具体功能

  • 界面：

    首先我给这个 shell 语言 就简单地叫 minishell 了，毕竟我文件命名就是用这个（），所以在刚进入 程序 的时候，就会给出一个欢迎界面：

    
 __  __ _       _ ____  _          _ _
|  \/  (_)_ __ (_) __ \| |__   ___| | |
| |\/| | | '_ \| |  \/ | '_ \ / _ \ | |
| |  | | | | | | | >  | | | |  __/ | |
|_|  |_|_|_| |_|_|_|\_\|_| |_|\___|_|_|

Type "code" to code style, "help" to show help

    • code 模式

      然后可以看到，它说的是，输入 code 可以进入 code 状态，这个 code 状态，其实就是类似于 Python 的命令行交互，如果涉及到未闭合的函数，表达式（后面会讲定义之类的）等，就会有 多行输入 和continuation prompt：

      >>> function add(a,b){
...>}
>>>

      但是，正常的函数，语句也可以在 code 模式外使用

      当然，在 code 模式里面，一些 外部命令 被我禁止了：

      >>> ls
minishell:code mode:external command 'ls' not allowed

      所以这个模式就只是为了好看，因为在正常使用的时候会有一些路径之类的东西，有点麻烦，所以弄了个这个模式

      然后这个状态可以输入 quit 退出

    • help

      这个命令就是列出所有 内置命令：

      MiniShell:~$ help
MiniShell builtins:cd pwd echo set alias jobs fg bg exit help code

  • 变量：

    • 声明与定义：

      这里我就参考 js 来做的一个变量的 声明与定义：

      let a=5 #给a赋值5
set a=5 #设置环境变量

      当前实现用的是类似于 弱类型 的思路（其实就是 js 的思路）：

      • 变量以字符串为基础存储，在需要做数值计算时会尝试把字符串解析为数值
      • 也就是说变量可以保存任意文本，但做算术时会先做类型转换（字符串 转成 整数或浮点数）

  • 运算：

    • 这里我定义了两种方式来进行运算：

      • `expr num1 <op> num2`

        • 注意一定要有 反引号 `....`
        • <op>：代表 +，-，*，/，%
        • 注意 num1 和 <op>，num2 和 <op> 之间一定要有空格

      • $((num1 <op> num2))

        • <op>：代表 +，-，*，/，%
        • num1 和 <op>，num2 和 <op> 之间不一定要有空格

    • 可以用 echo `expr num1 <op> num2` 或 echo $((num1 <op> num2))来输出计算结果

      • 比如：

        >>> echo `expr 1 + 3`
4
>>> echo $((1*3))
3

      • 但你如果只是 $((1+3)) 或 `expr 1 + 3`，它就只会把计算结果 4 当做命令：

        >>> $((1+3))
minishell:code mode:external command '4' not allowed

    • 然后 运算 的实现就是去 递归运算 （表达式生成 AST 后递归求值），目前仅支持 加减乘除

    • 当然了，从上面也可以看出来，$ 关键字其实就是用来变量替换

  • 语句：

    • 赋值语句：

      • 其实上面说了，就是 let a=b，这里的 a 是变量名，b 是给 a 赋的值

    • 条件语句：

      • 用 if 就可以了，我是设定的和 Python 的用法差不多：

        >>> let a=5
>>> if a==5 {
... echo 1
... }
1

        支持：==、!=、<、>

        当然由于没有实现 && 这些运算符，也没有 and 这些关键字，所以只是一个逻辑上很简单的实现

    • 循环语句：

      • 支持的形式为 for NAME in <items> { ... }，其中 <items> 可以是三类：

        1. 直接列举：

          MiniShell:~$ for i in a b c {
  echo $i $i_index
}
a 0
b 1
c 2
# 这里的 i_index 其实就代表 i 的下标

        2. 文件名展开：

          MiniShell:~$ for f in *.txt {
  echo $f
}
1.txt
2.txt
3.txt
# 假设当前目录下有以上三个.txt文件

        3. 命令替换：

          可以用反引号包住 `<command>` 来获得运算结果之后，在进行迭代（当然前面说过 code 模式是禁用 外部命令 的，所以有一些命令要在非 code 模式使用

          MiniShell:~$ for x in `ls *.txt` {
  echo $x
}
1.txt
2.txt
3.txt
# 依然是假设当前目录下有以上三个.txt文件

  • 函数：

    • 声明与定义

      • 我设定了两个关键字 def 和 function 用来定义函数：

        >>> def add(a,b){
... echo $((a+b))
... }
>>> add(3,4)
7
>>> function add(a,b){
... echo $((a*b+1))
... }
>>> add(3,2)
7

        然后的话 递归 是暂时没有实现的，所以也是逻辑上很简单的实现

  • 注释：

    • 用 # 注释：
      • 从 # 开始，到行尾结束

Code

这里就主要说一下几个与 解释器 相关的类或结构体，其他的就不赘述了，详情看代码

  • TokenType：

    • //Token system
enum class TokenType

    • 用于记录 关键字 和 token 类型

  • Token：

    • struct Token

    • 记录单个 token 的信息（类型、文本、位置信息等）

  • Lexer（词法分析）

    • class Lexer

    • 把输入字符串拆成 Token 列表

    • 实现了 readString, readNumber, readWord 等方法

    • 识别 $((...))、反引号命令替换、注释、字符串字面量、运算符和分隔符等

    • 具体实现可以看一下 Lexer::tokenize()。

  • Parser（语法分析）

    • class Parser

    • 把 Token 向量解析成 AST（以 Statement / Expression 为节点）

    • 实现了 parseStatement、parseLetStatement、parseIfStatement、parseForStatement、parseFunctionStatement、parseCommandOrPipeline 等解析函数，并能生成 CompoundStatement

  • MiniShellInterpreter（解释器）

    • 包含 Environment env、终端控制相关的字段（shell_terminal, shell_pgid, shell_tmodes），初始化时设置 signal/pgid 并把 ShellManager::setInstance(this) 注册为全局实例
    • 提供辅助方法：substituteVariables（代理到 StringProcessor）、expandAndSubstituteArgs、runCommandCaptureOutput、execute_builtin、execute_external 等
    • CommandStatement 与 CommandExpression 都通过 ShellManager::getInstance() 获取该实例并调用这些接口
