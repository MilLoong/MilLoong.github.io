❓CH1

用偏序关系外加逻辑运算符实现等价关系

  • 不是小于的且不是大于的，就是等于了

  • 这里为方便描述还是 define 一下

    #define equ(a, b) (!(a < b) && !(b < a))

用偏序和等价关系外加逻辑运算符实现其余四种比较运算符

  • 不等价 !=

    • 等价关系的否定：

      #define not_equ(a, b) (!equ(a, b))

  • 大于 >

    • 小于的反向，也就是反向的偏序：

      #define gra(a, b) (b < a)

  • 小于等于 <=

    • 大于的否定：

      #define less_equ(a, b) (!(b < a))

  • 大于等于 >=

    • 小于的否定：

      #define gra_equ(a, b) (!(a < b))

❓CH2

原代码 

  • int compare(int a, int b) {

    return a - b;

}

  • 问题：

    • 很显然，如果 a-b 超出 int 的范围，就会导致溢出，导致出现负数等问题

正确代码

  • 其实不需要用具体的值，直接用表示 a 和 b 大小关系的 bool 就行了

  • int compare(int a, int b) {

    return (a > b) - (a < b);

}

❓CH3

原代码

这里的 compare 我就视作和 CH2原代码 一样吧，不然用我上面改的代码来做我好像找不出什么问题（）

  • int reverse_compare(int a, int b) {

    return -compare(a, b);

}

  • 问题：

    • 我们知道 int 表示的范围是 $[2^{-31},2^{31}-1]$，所以如果直接取 - ，当 compare 返回的值是 $2^{-31}$时，再取负号就变成了 $2^{31}$ 那么就会导致溢出，变成负数

正确代码

  • 其实直接反转一下 a 和 b 就可以了：

    int reverse_compare(int a, int b) {

    return compare(b, a);

}

❓CH4

对于表达同样字符串的三种编码，字典序比较的结果是否相同？

  • 不一定相同

    既然编码不同，那肯定不一定相同吧（

  • 这个举个反例就好了：

    • S1 和 S2

      • UTF-8：
        • S1：F0 90 80 80
        • S2：EE 80 80
        • 由于 0xF0>0xEE 所以 S1>S2
      • UTF-16：
        • S1：D800 DC00
        • S2：E000
        • 由于 0xD800<0xE000 所以 S1<S2
      • UTF-32：
        • S1：00010000
        • S2：0000E000
        • 由于 0x00010000>0x0000E000 所以 S1>S2
      • 可以发现在这个例子中 UTF-8 和 UTF-32 的结果是相同的，均与 UTF-16 的结果不同

      然后是怎么证明 UTF-8 和 UTF-32 有可能不同，这个样例有点难找，然后我搜到了一个比较奇怪的反例（

    • Ā 和 A

      • UTF-8：
        • Ā：C4 80
        • A：41
        • 0xC4>0x41 所以 Ā>A
      • UTF-32LE（UTF-32 的小端序，大端序的话目前我没有找到qwq）：
        • Ā：00 01 00 00
        • A：41 00 00 00
        • 0x00<0x41 所以 Ā<A

    • 从这两个例子就可以证明比较的结果是不一定相同的了

❓CH4

  • 首先答案肯定还是，不完全相同（UTF-8 和 UTF-32 相同，均与 UTF-16 不同）

  • 由于题目中涉及到 char8_t，char16_t，char32_t，所以首先先来看一下他们的定义：

    • char8_t：
      • UTF-8 编码的代码单元
      • 一个字节
    • char16_t：
      • UTF-16 编码的代码单元
      • 两个字节
    • char32_t：
      • UTF-32 编码的代码单元，用于存储完整的 Unicode 码点
      • 四个字节

  • 理论上，相同的字符串在不同编码下进行字典序比较应该得到一致的结果

  • 不过这里要注意，UTF-16 有一个特殊的编码机制：代理对，这是 UTF-8 和 UTF-32 都没有的

    • 代理对是用来在 UTF-16 中表示补充字符的方法，它用两个对应于基本平面的码元（码元所对应的码点在基本平面中均未定义字符）来表示增补平面的码点值。

      简单来讲，对于所有大于 0xFFFF 的码点值，如果要编码成 UTF-16 ，就要用一个**“代理对”**来表示

    • 这样的话，UTF-16 使用代理对时，会用较小的代理码点来表示较大的 Unicode 码点，就可能导致字典序比较结果与实际码点大小不同

  • 举个反例：

    • 这里举反例的话就用上面的代理对的内容来构造就可以了。

    • UTF-16 的基本平面最大码点值是 0xFFFF 的话，我们可以直接拿其中一个字符的编号是 U+10000 ，查了一下它对应的字符是 𐀀。然后它对应的 UTF-16 编码，根据我们上面的代理对机制，是0xd800 0xdc00，所以要把它卡掉的话，就拿一个码点值小于 U+10000 ，但在 UTF-16 编码中第一个码元比 0xd800 大的字符就好了，显然拿 U+E000，对应的字符是 

    • 𐀀 和 ：

      • 然后这里我就不用纯理论分析了，不然容易像第一次提交的时候搞错（，所以就用程序来验证吧

      • 先把题目给的三个比较函数补全：

        int strcmp_utf8(const char8_t *s1, const char8_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

int strcmp_utf16(const char16_t *s1, const char16_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

int strcmp_utf32(const char32_t *s1, const char32_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

      • 然后分别用三种编码方式硬编码刚才说过的两个字符：

        const char8_t u8_s1[] = u8"𐀀";
const char8_t u8_s2[] = u8"";

const char16_t u16_s1[] = u"𐀀";
const char16_t u16_s2[] = u"";

const char32_t u32_s1[] = U"𐀀";
const char32_t u32_s2[] = U"";

      • 接着调试一下比较结果：

        std::cout << "UTF-8: ";

if (cmp8 > 0) std::cout << "𐀀 > \n";
else if (cmp8 < 0) std::cout << "𐀀 < \n";
else std::cout << "𐀀 = \n";

std::cout << "UTF-16: ";

else std::cout << "𐀀 = \n";

std::cout << "UTF-32: ";

      • 得到的结果是：

        UTF-8: 𐀀 > 

        可以看到确实 UTF-16 的结果和 UTF-8 与 UTF-32 均不同

  • 而 UTF-8 和 UTF-32 没有类似于代理对的机制，所以说他们的字符串比较结果通常是相同的

竟然忘了，最粗心的一集

证明 UTF-8 和 UTF-32 的字符串比较结果相同

  • UTF-32

    • 每个 Unicode 码点用固定的 4 字节表示

    • 字典序比较时，本质上就是直接比较码点值的大小

  • UTF-8

    • 可变长编码，长度为 1~4 字节

    • 是一种前缀码：不同长度的编码区间互不重叠。

      • 根据 UTF8, 16进制编码表 有：

        UTF8-1 0x00-0x7F
        UTF8-2 0xC2-0xDF 0x80-0xBF
        UTF8-3 0xE0 0xA0-0xBF 0x80-0xBF 0xE1-0xEC 0x80-0xBF 0x80-0xBF 0xED 0x80-0x9F 0x80-0xBF0xEE-0xEF 0x80-0xBF 0x80-0xBF
        UTF8-4 0xF0 0x90-0xBF 0x80-0xBF 0x80-0xBF0xF1-0xF3 0x80-0xBF 0x80-0xBF 0x80-0xBF0xF4 0x80-0x8F 0x80-0xBF 0x80-0xBF

      • 可以看出，对于所有合法 UTF-8 序列，不同长度的编码区间互不重叠且严格递增，因此较长编码的首字节区间整体大于较短编码的首字节区间，所以 较长编码对应的码点值一定更大

    • 编码规则确保：如果码点 A > B，那么它们对应的 UTF-8 字节序列在字典序下也满足 A > B

  • 思路

    这等价于证明：

    • UTF-8 编码的字节序列是 Unicode 码点值 的单调递增函数

    • 即如果 UTF-32(U+X) > UTF-32(U+Y)，则 UTF-8(U+X) > UTF-8(U+Y) （按 字节 字典序比较）

  • 分类讨论

    • 同一字节长度的情况：

      • 若 A 和 B 都是单字节（U+0000 .. U+007F）：编码结果就是码点本身，大小关系保持不变
      • 若 A 和 B 都是多字节：
        • UTF-8 是一种前缀码，首字节保存了高位信息，并且区分了编码长度
        • 后续字节都在 0x80..0xBF 范围内
        • 由于这是 高位在前 的逐字节比较，因此第一个 不同的字节 对应 原始码点 的大小关系，也就是说，如果 原始码点 是 A > B ，那么第一个 不同的字节 所对应的位置，也是 A 的大于 B 的（因为你 UTF-32 翻译成 UTF-8 的时候，也是按顺序翻译的，所以遵循 原始码点 的大小关系）

    • 不同字节长度的情况：

      • 假设 A 编码长度大于 B。

        • UTF-8 的设计保证：

          • 所有 2 字节编码的首字节区间（0xC2..0xDF） > 所有 1 字节编码（0x00..0x7F）

          • 所有 3 字节编码的首字节区间（0xE0..0xEF） > 所有 2 字节编码（0xC2..0xDF）

          • 所有 4 字节编码的首字节区间（0xF0..0xF4） > 所有 3 字节编码（0xE0..0xEF）

        • 因此 较长编码的首字节一定大于较短编码的首字节，从 第一个字节 就能直接比较出大小，保持与码点顺序一致

  • 结论

    • UTF-8 编码的字节序列是 码点值 的单调递增函数

    • 因此，UTF-8 和 UTF-32 的字符串比较结果是相同的
