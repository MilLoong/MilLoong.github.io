UTF-8、UTF-16、UTF-32 的字典序比较

背景

同一段字符串，分别用 UTF-8、UTF-16、UTF-32 存下来，再按 代码单元 做 字典序 比较，三种结果该不该一样？

代码单元 也叫 码元，是编码之后最小的那一格：UTF-8 一格 1 字节，UTF-16 16 位，UTF-32 32 位

码点 是 U+xxxx 那个编号，不是一种宽度。编号最大到 U+10FFFF，本身不占 4 字节。哪种编码、格子多宽，是存这个编号的时候才定的

一个码点 可以对应 一个 或 多个码元：

  • UTF-32：码元 4 字节，格子里直接写这个编号，所以 1 个码点 1 个码元
  • UTF-8：码元 1 字节，1 个码点 1~4 个字节
  • UTF-16：码元 2 字节。编号不超过 U+FFFF 时，同一个编号塞进一个 16 位格子，仍是 1 个码点 1 个码元；超出 U+FFFF 一个格子装不下，要 2 个码元，第一个落在 0xD800 .. 0xDBFF

比如码点 U+10000 的字符 𐀀：UTF-8 4 个字节，UTF-16 2 个码元，UTF-32 1 个码元

再拿一个码点更小的 U+E000（字符 ）。按 Unicode 码点，明明是 𐀀 > 。可 字典序 比的是 编码后 的码元值，不是码点本身

编码变长之后，同一对字符会不会翻成 𐀀 < ？

C++ 里三种 代码单元 是：

  • char8_t：UTF-8，一个字节
  • char16_t：UTF-16，两个字节
  • char32_t：UTF-32，四个字节，存完整 Unicode 码点

比较函数都长一个样，只是 指针类型不同，逐个单元比过去：

int strcmp_utf8(const char8_t *s1, const char8_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

int strcmp_utf16(const char16_t *s1, const char16_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

int strcmp_utf32(const char32_t *s1, const char32_t *s2) {
    while (*s1 && *s2) {
        if (*s1 < *s2) return -1;
        if (*s1 > *s2) return 1;
        ++s1;
        ++s2;
    }
    if (*s1) return 1;
    if (*s2) return -1;
    return 0;
}

相信看完本文你会有答案

为什么 UTF-16 会和 UTF-8、UTF-32 不同

同一对 𐀀 和 ：UTF-8 和 UTF-32 都是 𐀀 > ，UTF-16 是 𐀀 < 。UTF-8 和 UTF-32 相同，和 UTF-16 不同

原因是 UTF-16 独有的 代理对。UTF-8 和 UTF-32 都没有这个东西

Unicode 基本平面（BMP）是 U+0000 到 U+FFFF。大于 0xFFFF 的码点在 UTF-16 里塞不进一个 char16_t，就要用 两个码元 拼起来，叫 代理对：

  • 高代理：0xD800 .. 0xDBFF
  • 低代理：0xDC00 .. 0xDFFF

这两个区间在 BMP 里没有定义字符，专门拿来当 半个增补平面码点。换算是：

cp' = cp - 0x10000
high = 0xD800 + (cp' >> 10)
low  = 0xDC00 + (cp' & 0x3FF)

于是所有大于 0xFFFF 的码点，编码出来的 第一个码元都落在 0xD800 .. 0xDBFF，比不少 BMP 字符还小

也就是说，UTF-16 会用 较小 的代理码点去表示 较大 的 Unicode 码点，字典序 就可能和实际码点对不上

反例就按这个来造。基本平面最大是 0xFFFF，拿刚出界的 U+10000，对应 𐀀。代入上面的式子：

0x10000 - 0x10000 = 0
high = 0xD800
low  = 0xDC00

再拿一个码点小于 U+10000、但第一个码元比 0xD800 大的字符。显然拿 U+E000，对应 ，它还在 BMP 里，UTF-16 就是一个码元 0xE000

按码点：0x10000 > 0xE000，应该 𐀀 > 

按 UTF-16 第一个码元：0xD800 < 0xE000，变成 𐀀 < 

输出结果

我不用纯理论分析了，不然容易搞错，直接硬编码这两个字符跑一遍

const char8_t u8_s1[] = u8"𐀀";
const char8_t u8_s2[] = u8"";

const char16_t u16_s1[] = u"𐀀";
const char16_t u16_s2[] = u"";

const char32_t u32_s1[] = U"𐀀";
const char32_t u32_s2[] = U"";

把代码单元打成十六进制，比较函数就是上面那三个：

void print_utf8(const char8_t *s) {
    while (*s) {
        std::cout << "0x" << std::hex << std::setw(2) << std::setfill('0')
                  << (unsigned int)(unsigned char)*s << " ";
        ++s;
    }
    std::cout << std::dec << std::endl;
}

void print_utf16(const char16_t *s) {
    while (*s) {
        std::cout << "0x" << std::hex << std::setw(4) << std::setfill('0')
                  << (unsigned int)*s << " ";
        ++s;
    }
    std::cout << std::dec << std::endl;
}

void print_utf32(const char32_t *s) {
    while (*s) {
        std::cout << "0x" << std::hex << std::setw(8) << std::setfill('0')
                  << (unsigned int)*s << " ";
        ++s;
    }
    std::cout << std::dec << std::endl;
}

int main() {
    std::cout << "UTF-8  s1: "; print_utf8(u8_s1);
    std::cout << "UTF-8  s2: "; print_utf8(u8_s2);
    std::cout << "UTF-16 s1: "; print_utf16(u16_s1);
    std::cout << "UTF-16 s2: "; print_utf16(u16_s2);
    std::cout << "UTF-32 s1: "; print_utf32(u32_s1);
    std::cout << "UTF-32 s2: "; print_utf32(u32_s2);

    std::cout << "UTF-8: ";
    int cmp8 = strcmp_utf8(u8_s1, u8_s2);
    if (cmp8 > 0) std::cout << "𐀀 > \n";
    else if (cmp8 < 0) std::cout << "𐀀 < \n";
    else std::cout << "𐀀 = \n";

    std::cout << "UTF-16: ";
    int cmp16 = strcmp_utf16(u16_s1, u16_s2);
    if (cmp16 > 0) std::cout << "𐀀 > \n";
    else if (cmp16 < 0) std::cout << "𐀀 < \n";
    else std::cout << "𐀀 = \n";

    std::cout << "UTF-32: ";
    int cmp32 = strcmp_utf32(u32_s1, u32_s2);
    if (cmp32 > 0) std::cout << "𐀀 > \n";
    else if (cmp32 < 0) std::cout << "𐀀 < \n";
    else std::cout << "𐀀 = \n";
}

比较结果：

UTF-8: 𐀀 > 
UTF-16: 𐀀 < 
UTF-32: 𐀀 > 

可以看到，UTF-16 与 UTF-8、UTF-32 不同

编码也能对上刚才的推导：𐀀 的 UTF-8 首字节 0xF0 大于  的 0xEE，UTF-32 是 0x00010000 > 0x0000E000，UTF-16 则是 0xD800 0xDC00 对上 0xE000，0xD800 < 0xE000

为什么 UTF-8 和 UTF-32 相同

UTF-8 和 UTF-32 没有代理对，比较结果通常相同

要说明的是：UTF-8 按字节从左往右比，UTF-32 按码点比，这两种比法 总是 相同

UTF-32 在比什么

每个 Unicode 码点固定 4 字节

字典序比较时，本质上就是直接比较 码点值 的 大小

U+10000 > U+E000，所以 𐀀 > 

UTF-8 的编码区间

UTF-8 是可变长编码，长度 1~4 字节，而且是 前缀码：不同长度的编码区间互不重叠。按十六进制编码表：

长度 编码区间
UTF8-1 0x00-0x7F
UTF8-2 0xC2-0xDF，后续 0x80-0xBF
UTF8-3 0xE0 + 0xA0-0xBF + 0x80-0xBF；0xE1-0xEC / 0xEE-0xEF + 0x80-0xBF + 0x80-0xBF；0xED + 0x80-0x9F + 0x80-0xBF
UTF8-4 0xF0 + 0x90-0xBF + 两段 0x80-0xBF；0xF1-0xF3 + 三段 0x80-0xBF；0xF4 + 0x80-0x8F + 两段 0x80-0xBF

合法序列里，不同长度的编码区间互不重叠且严格递增

较长编码 的 首字节 整体大于 较短编码的首字节，所以 较长编码 对应的码点 一定更大

编码规则也保证：若码点 A > B，它们的 UTF-8 字节序列在 字典序 下也是 A > B

证明 UTF-8 和 UTF-32 相同

这等价于证明：

UTF-8 编码的字节序列是 Unicode 码点值的 单调递增 函数

也就是：UTF-32(U+X) > UTF-32(U+Y) 时，UTF-8 按字节从左往右比也有 UTF-8(U+X) > UTF-8(U+Y)

分类讨论：

同一字节长度

  • 都是 单字节（U+0000 .. U+007F）：编码就是码点本身，大小关系不变
  • 都是 多字节：首字节存高位并区分长度，后续字节都在 0x80..0xBF。这是 高位在前 的逐字节比较，第一个不同的字节就对应原始码点的大小关系。UTF-32 翻译成 UTF-8 也是按顺序翻的，所以第一个不同字节那边，A 仍然大于 B

不同字节长度

假设 A 的编码比 B 长。UTF-8 的设计保证：

  • 所有 2 字节首字节（0xC2..0xDF）大于所有 1 字节（0x00..0x7F）
  • 所有 3 字节首字节（0xE0..0xEF）大于所有 2 字节
  • 所有 4 字节首字节（0xF0..0xF4）大于所有 3 字节

所以较长编码的 首字节 一定更大，从 第一个字节 就能比出：编码更长 的那个 UTF-8 更大，编码更长 对应的 码点 也更大。UTF-8 按字节从左往右比，和 按编号比 是一样的

𐀀 是 4 字节（首字节 0xF0）， 是 3 字节（首字节 0xEE），0xF0 > 0xEE。码点也是 U+10000 > U+E000，同一边，不会像 UTF-16 那样翻

因此 UTF-8 和 UTF-32 的字符串比较结果相同

结论

同一对字符按 代码单元 做字典序：

  • UTF-32 比的就是 码点
  • UTF-8 的 首字节区间 跟着 码点长度 单调往上走，和 码点顺序一致
  • UTF-16 的增补平面被压进 0xD800 开头的 代理对，第一个码元 可能比后面那些 BMP 字符还小

所以同一对 𐀀 和 ：UTF-8、UTF-32 都是 𐀀 > ，UTF-16 是 𐀀 < 。不完全相同：UTF-8 和 UTF-32 相同，均与 UTF-16 不同
