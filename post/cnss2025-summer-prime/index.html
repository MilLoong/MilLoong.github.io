🧮Prime

✍问题一

  • 本题筛素数的协程用了生成器，叫做 基于生成器的协程（generator-based coroutine）。 而我稍微搜了一下，其实可以更详细一点：

    • 它是 非对称协程（asymmetric coroutine）：挂起时控制权返回给调用者，而不是任意协程之间切换；
    • 它是 非栈式协程（stackless coroutine）：只保存 Python/JS 的执行帧，不保存完整的原生调用栈，因此不能在任意深度的普通函数中间点挂起；
    • 它是 第一类对象协程（first-class coroutine）：生成器对象可以自由创建、赋值、传递和组合，不受限于特定的语法结构。
    • 它是 嵌套协程（nested coroutine）：每层 filter 都生成一个新的生成器对象，包装前一层生成器，形成层层嵌套的协程结构，控制流从内层逐层传回外层，实现多层筛选逻辑。

  • 这题就是一个基于携程的简单的 埃式筛（埃拉托斯特尼筛法）

    • 大致原理：

      • 对于大于 1 的整数n，它的 $x$ 倍（$x>1$）就是合数；
      • 所以就可以从小到大考虑每一个数，然后把当前这个数的倍数 $nx$ 标记为合数（$nx>n$）
      • 这样子的话运行结束时没有被标记的就都是素数了

    • 时间复杂度：

      • 这里简要说一下大致的思路，具体的证明不赘述

        • 如果要筛掉 [1,n] 中所有的数的倍数，那它的时间复杂度是调和级数： $$ \sum^{n}_{k=1}\lfloor{\frac{n}{k}}\rfloor\approx nlogn $$

    • 那现在是要筛掉所有素数的倍数，可以证明时间复杂度就是：

    $$ \sum_{p\leqslant n,p\in prime}{\lfloor\frac{n}{p}\rfloor}=nloglogn $$

    ​ 所以埃式筛的时间复杂度是

    $$O(nloglogn)$$

基于协程的埃式筛

  • iota
- `iota(i, n)` 是一个**序列生成器**，会依次产生区间 `[i, n)` 的整数。



- 在本题中，`iota(2, 100)` 就生成了从 `2` 到 `99` 的整数流，作为筛法的初始数据源。

  • filter

    • filter(g, p) 可以理解为过滤器生成器：它接收一个生成器 g，只向外 yield 不是 p 的倍数的值。

    • 这样就实现了“筛掉所有 p 的倍数”的效果。

  • 主函数逻辑

    • 主循环中，每次取到一个 value（即一个素数），就用 filter 包装当前生成器，得到一个新的生成器 g：

        value = next(g)

  g = filter(g, value)

  ```

    • 这样，生成器的结构就逐步变成了嵌套形式：

      $$ g = filter(filter(\dots filter(iota, p_1), p_2), \dots, p_k) $$

    • 其中，每一层 filter 都会记住当时的素数 p（这个特性和闭包类似，后续代码错误的原因也和闭包有关），并在后续迭代时持续生效。

    • 当新的数流经过这些嵌套的过滤器时，就会被逐层筛掉对应素数的倍数，最终剩下的就是素数序列。

✍问题二

🤔为什么有问题？

  • 第二份代码和第三份代码用的都是内置的 filter 函数，而里面传的第一个参数用的是（以第二份代码为例）：

    lambda incoming: incoming % value

    这是一个lambda表达式：

    • incoming：filter从传入的第二个参数（生成器 g ）里取的一个元素
    • value：从外部作用域捕获的变量引用

    由于 lambda 捕获的是 变量引用，而 value 会在主循环中不断变化，所有内层 filter 其实都在使用 同一个最新的 value 进行判断。

    那这样在最外层filter或许传入的 value 是对的，但到内层的filter的时候，筛的数仍然是 value 的倍数，那结果自然就不对了。

🤔问题一样吗？

  • 这样看来，两者的问题是一样的，并不取决于 Python 或 JS 内置 filter 的实现，而是由于 lambda 捕获外部变量时保存的是 引用（类似闭包的特性），导致嵌套的 filter 条件共享了同一个变量，筛选逻辑被破坏。

✍问题三

由于 lambda 捕获的是外层变量的引用，直接使用外部变量会导致内层 filter 逻辑错误（value不对），所以我们需要在创建函数时固定当前值。

  • 💻第二份代码修改

    把g=filter(lambda incoming: incoming % value, g)改成：

    g=filter(lambda incoming, p=value: incoming % p, g)

    这里 p=value 会把当前 value 的值固定在 lambda 内部，避免随着外层循环变化而被覆盖。

def iota(i, n):

    while i < n:

        yield i

        i += 1



g = iota(2, 100)

try:

    while True:

        value = next(g)

        g = filter(lambda incoming, p=value: incoming % p, g)

        print(value)

except StopIteration:

    pass

  • 💻第三份代码修改

    把g = filter(g, incoming => incoming % value)改成：

    g = filter(g, ((p) => (x) => x % p)(value))

    这里通过立即执行函数 (IIFE) 固定了当时的 value，生成新的函数供 filter 使用，从而避免闭包共享同一变量引用的问题。

function* iota(i, n) {

  while (i < n) yield i++;

}



function* filter(g, p) {

  for (const x of g) {

    if (p(x)) yield x;

  }

}



let g = iota(2, 100);

while (true) {

  const { value, done } = g.next();

  if (done) break;

  g = filter(g, ((p) => (x) => x % p)(value));

  console.log(value);

}
