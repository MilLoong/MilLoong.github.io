现代 C++ 应用：设计线程池

概述

本文可以当做是 现代 C++ 教程 的学习笔记

线程池 是一种用来 调度 多个线程 去 并行 执行任务 的设计，能 提高系统性能，减少 执行任务 的 时间，具体包括：

  • 任务队列
  • 执行任务
  • 提交任务

简单来说就是一个 生产者——消费者 模型，类似于 MQ

那么本篇文章将会使用 现代 C++ 的语法特性，主要是 C++ 11 的 std::thread、智能指针、RAII 等，以及部分 C++ 20 及往后的语法，比如 C++ 20 的 std::jthread 和 stop_token，C++ 26 的 匿名变量 等，来设计一个 线程池

基本设计

下面的代码是用 C++ 11 的特性

任务队列

这个就很简单，一个 std::queue 即可，然后这个队列里面可以放一个 std::function<void()>，即 无参无返回值 的 可调用对象

不过和 MQ 一样，这个 std::queue 其实是一个 共享变量，多个线程 要去取它，所以要加一个 std::mutex，保证每个时刻 只有一个线程 拥有锁 并 取一条任务

执行任务

每个 线程 要去从 任务队列 里取一个 std::function<void()> 并在内部执行，前面说过要给 队列 加锁，所以这里就可以用 mutex 的 RAII 包装，也就是 std::lock_guard<std::mutex> 或 std::unique_lock<std::mutex>

考虑到它其实是要 等待以下任一条件成立 才能取 任务：

  • 队列非空
  • 线程池停止，这里是因为可能 线程池停了 但 任务队列 还有任务，这时候就要继续执行任务

所以需要一个 条件变量，这时候就要选择 std::unique_lock，因为只有它才会在 条件变量 等待时 释放锁，并在满足条件后获得锁

接下来就在 锁 的作用域 里取到任务，然后 离开锁的作用域再执行，任务本身不要在持锁时跑，否则其它 worker 会被堵住

执行的过程中如果遇到 线程池停止 且 队列为空 就说明已经结束了，直接 break

代码如下：

void worker_loop() {
    while (1) {
        std::function<void()> task;
        {
            std::unique_lock<std::mutex> lock(mutex_);
            cv_.wait(lock, [this] {
                return stop_ || !tasks_.empty();
            });
            if (stop_ && tasks_.empty()) {
                break;
            }
            task = std::move(tasks_.front());
            tasks_.pop();
        }
        task();
    }
}

提交任务

任务入队

先来看一下怎么 直接往队列里面扔 std::function<void()>

那这个就很简单，过程就是：

  • 获取 锁
  • 如果 线程池已经停了，就抛出异常
  • 加入队列
  • 释放锁
  • 唤醒一个等待的线程
void enqueue(std::function<void()> task) {
    {
        std::lock_guard<std::mutex> lock(mutex_);
        if (stop_) {
            throw std::runtime_error("线程池已停止，无法提交新任务");
        }
        tasks_.push(std::move(task));
    }
    cv_.notify_one();
}

任务提交

上面的这个 直接 push std::function 进到 任务队列 里面的写法，其实是有个弊端的，因为可能有需求是 线程执行完之后，需要获取线程执行的结果，那上面的代码就办不到

对于这种 开一个线程执行一个任务，然后直接拿结果，我们可以用 std::async + std::future<T>，但在 线程池设计 的场景下并不适用，我们期望的是 把一个任务放到任务队列里，由池内线程延迟执行，std::async 默认启动策略是实现定义的，可能立刻起新线程，也可能推迟到 get() / wait()，而且 不会复用你自己的那一组 worker

这时候就可以用 std::packaged_task，它相当于把 task 打包，本质上是封装了 std::future<T> + std::promise，这样子的话就可以在 线程 执行完任务之后，返回一个 std::future<T> 来取值了

这个 submit 函数的话就应该要设计成 函数模板，并返回 std::future<T>，提供的参数是 函数 及其 参数，内部负责 把 函数 及其 参数 封装成 std::packaged_task，然后提交到 任务队列 当中

参数

参数的话，前面说过，是 函数 及其 参数，这个在 函数模板 中是这么写的：

template<typename F, typename... Args>
auto submit(F&& f, Args&&... args);
返回值

这里的话要推测 F, Args... 的 返回值类型 的，在这里可以用 C++ 17 的 类型萃取 std::invoke_result_t，所以上面的代码可以写成这样：

template<typename F, typename... Args>
auto submit(F&& f, Args&&... args)
    -> std::future<std::invoke_result_t<F, Args...>> {
    using ReturnType = std::invoke_result_t<F, Args...>;
    // TODO
}
封装

封装成 std::packaged_task 的话，要注意两个问题：

  • std::packaged_task 是 move-only 的，所以要加个 std::make_shared，用一个 shared_ptr 指向它，否则后面加入队列的那个 lambda 不能拷贝，就放不进 std::function

  • 由于这里 submit 的参数是有 函数 的 参数 args 的，而 std::function<void()> 是要求无参的，所以在后面 push 进去的 lambda 不能有参数，这样的话可以把 args 绑定到 std::packaged_task 里，这里有两种方法：

    • std::bind：

      std::make_shared<std::packaged_task<ReturnType()>>(
    std::bind(std::forward<F>(f), std::forward<Args>(args)...)
);

    • 提前捕获参数的 lambda：

      • 这个方法的话要改一下 submit 的形参，改成只有一个 typename F，然后这个 F 就是 捕获了参数的 lambda，这样的话就只需要：

        std::make_shared<std::packaged_task<ReturnType()>>(std::forward<F>(f));

这里第二个问题我就用 std::bind 了，整合起来是这样：

auto task = std::make_shared<std::packaged_task<ReturnType()>>(
    std::bind(std::forward<F>(f), std::forward<Args>(args)...)
);

然后就获取一下 std::future：

std::future<ReturnType> fut = task->get_future();
入队

这里 入队 的其实是个 lambda 对象，然后就和上面 任务入队 一样了：

{
    std::lock_guard<std::mutex> lock(mutex_);
    if (stop_) {
        throw std::runtime_error("线程池已停止，无法提交新任务");
    }
    tasks_.push([task] {
        (*task)();
    });
}
cv_.notify_one();
整合

整合之后 submit 就是这样：

template <typename F, typename... Args>
auto submit(F&& f, Args&&... args)
    -> std::future<std::invoke_result_t<F, Args...>> {
    using ReturnType = std::invoke_result_t<F, Args...>;
    auto task = std::make_shared<std::packaged_task<ReturnType()>>(
        std::bind(std::forward<F>(f), std::forward<Args>(args)...)
    );
    std::future<ReturnType> fut = task->get_future();
    {
        std::lock_guard<std::mutex> lock(mutex_);
        if (stop_) {
            throw std::runtime_error("线程池已停止，无法提交新任务");
        }
        tasks_.push([task] {
            (*task)();
        });
    }
    cv_.notify_one();
    return fut;
}

构造

构造 的时候要传入 开启线程数量，以及对每个线程开启 worker_loop：

explicit ThreadPool(std::size_t num_threads) {
    for (std::size_t i = 0; i < num_threads; ++i) {
        workers_.emplace_back([this]() {
            worker_loop();
        });
    }
}

析构

析构 的时候要先 停止线程池，即把 stop_ 设为 1，注意这个 stop_ 也是共享变量，所以要在持锁时修改，否则：

  • 和 wait 谓词里读 stop_ 构成 数据竞争
  • 也可能和条件变量配合不当，出现 丢失唤醒

然后去 唤醒所有线程，去 执行剩余任务 或 宣告停止的条件成立

最后 join 所有线程即可：

~ThreadPool() {
    {
        std::lock_guard<std::mutex> lock(mutex_);
        stop_ = 1;
    }
    cv_.notify_all();
    for (auto& worker : workers_) {
        worker.join();
    }
}

异常传播

由于 出现异常之后，std::packaged_task 会将异常写在 共享状态 当中，然后在 std::future 的 get() 当中抛出，所以注意要调用 get()，不调用的话，结果和异常都拿不到，共享状态析构后异常也就不再可观测

另外：如果用 enqueue 直接丢进队列的是会抛异常的裸任务，异常会从 worker_loop 里的 task() 往外抛，worker 线程未捕获就会 std::terminate，要传播异常，应走 submit + future.get()

整合

最后 整合到 类 里，注意 线程池 是不允许 拷贝构造，拷贝赋值，移动构造，移动赋值 的，以及 成员声明顺序 要注意

析构时先执行析构函数体（join 完所有线程），再按 声明的逆序 销毁成员，workers_ 要声明在最后，保证其它成员还活着时线程已经全部 join 完，一种稳妥顺序是：

  • 先声明：stop_、mutex_、tasks_、cv_
  • 最后声明：workers_
#include <condition_variable>
#include <functional>
#include <future>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <vector>

class ThreadPool {
private:
    bool stop_{0};
    std::mutex mutex_;
    std::queue<std::function<void()>> tasks_;
    std::condition_variable cv_;
    std::vector<std::thread> workers_;

    void worker_loop() {
        while (1) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                cv_.wait(lock, [this] {
                    return stop_ || !tasks_.empty();
                });
                if (stop_ && tasks_.empty()) {
                    break;
                }
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            task();
        }
    }
public:
    explicit ThreadPool(std::size_t num_threads) {
        for (std::size_t i = 0; i < num_threads; ++i) {
            workers_.emplace_back([this]() {
                worker_loop();
            });
        }
    }

    ~ThreadPool() {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            stop_ = 1;
        }
        cv_.notify_all();
        for (auto& worker : workers_) {
            worker.join();
        }
    }

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;
    ThreadPool(ThreadPool&&) = delete;
    ThreadPool& operator=(ThreadPool&&) = delete;

    void enqueue(std::function<void()> task) {
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stop_) {
                throw std::runtime_error("线程池已停止，无法提交新任务");
            }
            tasks_.push(std::move(task));
        }
        cv_.notify_one();
    }

    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>> {
        using ReturnType = std::invoke_result_t<F, Args...>;
        auto task = std::make_shared<std::packaged_task<ReturnType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );
        std::future<ReturnType> fut = task->get_future();
        {
            std::lock_guard<std::mutex> lock(mutex_);
            if (stop_) {
                throw std::runtime_error("线程池已停止，无法提交新任务");
            }
            tasks_.push([task] {
                (*task)();
            });
        }
        cv_.notify_one();
        return fut;
    }
};

现代 C++ 优化

这一节分两块：

  • C++ 20：std::jthread + stop_token，去掉手写 join 和 stop_
  • C++ 26：匿名变量，去掉只为吊生命周期而起的临时名字

C++ 20：std::jthread + stop_token

在 C++ 20 中添加了 std::jthread + stop_token 机制，能 自动 join，协作取消，具体的功能不在本篇文章赘述，你只需要知道：

  • stop_source：每个 std::jthread 自带的一个 停止源，和对应的 stop_token 共享一个 停止状态
  • stop_token：与某 stop_source 对应的 停止令牌，可以 作为参数传入到 jthread 对应线程执行的 函数 中，就可以 协作取消，即 告诉 线程 自己要退出了，等待 这个线程 执行完某个任务之后自行退出
  • stop_requested：查看 共享的 停止状态，如果为 1 说明已经收到停止请求
  • request_stop：stop_source 发送停止请求
  • std::condition_variable_any：由于 std::condition_variable 没有带 stop_token 的重载，而我们稍后会用到，所以这里要用的是 std::condition_variable_any

用每个 jthread 自身的 stop_source

我们要优化的就是 线程手动 join，手动设置 stop_ 表示停止

手动 join 其实直接改成 std::jthread 就能解决问题了，这里主要说怎么优化 手动设置 stop_

先采用最直接的做法：让 每个 std::jthread 用自身的 stop_source

  • 构造时写成 [this](std::stop_token st) {...}，此时 st 就是 该 jthread 自动传入的、和自身 stop_source 绑定的 stop_token
  • 析构时对每个 worker.request_stop()
  • 条件变量改成 cv_any_.wait(lock, st, pred)

wait(lock, st, pred) 的返回值是 pred() 的当前值：

  • pred 为真时返回 1，表示可以继续取任务
  • 收到停止请求后也会醒来，再求一次 pred
    • 队列里还有任务：pred 仍为真，返回 1，继续把剩余任务做完
    • 队列已空：pred 为假，返回 0，worker 可以退出

因此不必再单独维护一个 stop_ 布尔量

构造：

explicit ThreadPool(std::size_t num_threads) {
    for (std::size_t i = 0; i < num_threads; ++i) {
        workers_.emplace_back([this](std::stop_token st) {
            worker_loop(st);
        });
    }
}

worker_loop：

void worker_loop(std::stop_token st) {
    while (1) {
        std::function<void()> task;
        {
            std::unique_lock<std::mutex> lock(mutex_);
            if (!cv_any_.wait(lock, st, [this] {
                return !tasks_.empty();
            })) {
                // 已停止，且队列为空
                return;
            }
            task = std::move(tasks_.front());
            tasks_.pop();
        }
        task();
    }
}

析构：

~ThreadPool() {
    for (auto& worker : workers_) {
        worker.request_stop();
    }
    cv_any_.notify_all();
}

std::jthread 析构时会自动 join，所以这里不用再手写 join 循环

那 submit 里怎么判断 线程池是不是已经停了？理论上来讲可以看成：

  • 有一个 std::jthread 已经收到了停止请求

也就是这样：

bool stop_requested() const {
    return !workers_.empty() && workers_[0].get_stop_source().stop_requested();
}

但这样写会有点问题，就是有可能 workers_ 为空，那么它会 一直返回 0，代表一直不停止

虽然 构造函数 在 num_threads == 0 时本来就不会起 worker，但这样的话在语义上其实也不通顺

具体怎么解决看下文，这里先暂时这么写

之前要用到 stop_ 的地方就可以改成 stop_requested()：

// 原
if (stop_) {
    throw std::runtime_error("线程池已停止，无法提交新任务");
}

// 现
if (stop_requested()) {
    throw std::runtime_error("线程池已停止，无法提交新任务");
}

改成线程池统一的 stop_source

上面用 其中一个 std::jthread 的 stop_requested 为 1 来判断是否线程池停止 不太好，所以这里有个更顺的方案：

  • 判断线程池是否停止，用一个 统一的 stop_source，而不是每个 std::jthread 里自带的那个
  • 这个统一的 stop_source 属于 线程池本身，和 workers_ 是否为空无关

创建统一的 stop_source 后，各个 std::jthread 对应的线程里传入 同一个 stop_token，再由这个 stop_source 统一 request_stop 即可

修改部分如下：

  • 构造

    // 原：吃每个 jthread 自身的 stop_token
explicit ThreadPool(std::size_t num_threads) {
    for (std::size_t i = 0; i < num_threads; ++i) {
        workers_.emplace_back([this](std::stop_token st) {
            worker_loop(st);
        });
    }
}

// 现：传入线程池统一的 stop_token
explicit ThreadPool(std::size_t num_threads) : stop_source_() {
    for (std::size_t i = 0; i < num_threads; ++i) {
        auto st = stop_source_.get_token();
        workers_.emplace_back(std::jthread([this, st] {
            worker_loop(st);
        }));
    }
}

    注意现写法的 lambda 不要 再带 (std::stop_token st) 形参，否则吃到的又是该 jthread 自己的 token，和 stop_source_ 不是同一个停止状态

  • 析构

    // 原
~ThreadPool() {
    for (auto& worker : workers_) {
        worker.request_stop();
    }
    cv_any_.notify_all();
}

// 现
~ThreadPool() {
    stop_source_.request_stop();
    cv_any_.notify_all();
}

  • submit 里判断是否停止：

    // 原
if (stop_requested()) {...}

// 现
if (stop_source_.stop_requested()) {...}

C++ 26：匿名变量

C++ 26 的 匿名变量 适合这种情形：

  • 返回值 不用拿来读改，只需要 一个变量维持生命周期
  • 这时不必再起一个只会写一次的名字

submit 里原来是：

{
    std::lock_guard<std::mutex> lock(mutex_);
    if (stop_source_.stop_requested()) {
        throw std::runtime_error("线程池已停止，无法提交新任务");
    }
    tasks_.push([task] {
        (*task)();
    });
}

这里 完全用不到 lock 这个名字，可以改成：

{
    auto _ = std::lock_guard<std::mutex>(mutex_);
    if (stop_source_.stop_requested()) {
        throw std::runtime_error("线程池已停止，无法提交新任务");
    }
    tasks_.push([task] {
        (*task)();
    });
}

整合

下面把 统一 stop_source 的 C++ 20 写法 和 C++ 26 的匿名变量 合在一起：

#include <condition_variable>
#include <functional>
#include <future>
#include <mutex>
#include <queue>
#include <stdexcept>
#include <stop_token>
#include <thread>
#include <type_traits>
#include <vector>

class ThreadPool {
private:
    std::stop_source stop_source_;
    std::mutex mutex_;
    std::queue<std::function<void()>> tasks_;
    std::condition_variable_any cv_any_;
    std::vector<std::jthread> workers_;

    void worker_loop(std::stop_token st) {
        while (1) {
            std::function<void()> task;
            {
                std::unique_lock<std::mutex> lock(mutex_);
                if (!cv_any_.wait(lock, st, [this] {
                    return !tasks_.empty();
                })) {
                    return;
                }
                task = std::move(tasks_.front());
                tasks_.pop();
            }
            task();
        }
    }
public:
    explicit ThreadPool(std::size_t num_threads) : stop_source_() {
        for (std::size_t i = 0; i < num_threads; ++i) {
            auto st = stop_source_.get_token();
            workers_.emplace_back(std::jthread([this, st] {
                worker_loop(st);
            }));
        }
    }

    ~ThreadPool() {
        stop_source_.request_stop();
        cv_any_.notify_all();
    }

    ThreadPool(const ThreadPool&) = delete;
    ThreadPool& operator=(const ThreadPool&) = delete;
    ThreadPool(ThreadPool&&) = delete;
    ThreadPool& operator=(ThreadPool&&) = delete;

    template <typename F, typename... Args>
    auto submit(F&& f, Args&&... args)
        -> std::future<std::invoke_result_t<F, Args...>> {
        using ReturnType = std::invoke_result_t<F, Args...>;
        auto task = std::make_shared<std::packaged_task<ReturnType()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );
        std::future<ReturnType> fut = task->get_future();
        {
            auto _ = std::lock_guard<std::mutex>(mutex_);
            if (stop_source_.stop_requested()) {
                throw std::runtime_error("线程池已停止，无法提交新任务");
            }
            tasks_.push([task] {
                (*task)();
            });
        }
        cv_any_.notify_one();
        return fut;
    }
};

若编译器还没有 C++ 26，把 auto _ = std::lock_guard<std::mutex>(mutex_); 改回带名字的 std::lock_guard<std::mutex> lock(mutex_); 即可，前面的 C++ 20 部分不受影响

测试

如果你有兴趣，可以使用下面的代码对写的 线程池 进行 测试

#include <iostream>
#include <stdexcept>
#include <string>

void test_submit() {
    ThreadPool pool(4);

    auto compute = [](int x) -> int {
        return x * x;
    };

    auto f1 = pool.submit(compute, 3);
    auto f2 = pool.submit(compute, 5);
    auto f3 = pool.submit([]() -> std::string {
        return "hello from thread pool\n";
    });

    std::cout << "=========测试 submit=========\n";
    std::cout << "f1: " << f1.get() << "\n";
    std::cout << "f2: " << f2.get() << "\n";
    std::cout << "f3: " << f3.get() << "\n";
}

void test_exception_spread() {
    ThreadPool pool(2);

    auto risky_task = [](int x) {
        if (x < 0) {
            throw std::invalid_argument("参数不能为负");
        }
        return x * x;
    };

    std::cout << "=========测试 异常传播=========\n";

    // 正常路径
    std::cout << "正常路径: \n";
    auto f1 = pool.submit(risky_task, 5);
    try {
        std::cout << "结果: " << f1.get() << "\n";
    } catch (const std::exception& e) {
        std::cout << "异常（不该走到这里）" << e.what() << "\n";
    }

    // 异常路径
    std::cout << "异常路径: \n";
    auto f2 = pool.submit(risky_task, -3);
    try {
        int res = f2.get();
        std::cout << "结果: " << res << "\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "捕获到异常: " << e.what() << "\n";
    }
}

int main() {
    test_submit();
    test_exception_spread();
    return 0;
}
